# Feature Specification: 남은 보안 과제 정리 (댓글 비밀번호·로그아웃 표·탈퇴 회원 댓글)

**Feature Branch**: `001-security-gap-fixes`

**Created**: 2026-10-07

**Status**: Implemented (2026-10-07)

**Input**: User description: "requirements.md 7·8장의 남은 과제 중 보안·데이터 일관성 3건을 고친다 — 방문자 댓글 삭제 비밀번호에 틀린 횟수 제한을 넣고 주소 대신 본문으로 보내기, 로그아웃 표를 회원에 묶고 1회용으로 바꾸기, 관리자가 회원을 탈퇴시킬 때 답글이 달린 그 회원의 댓글을 '삭제된 댓글입니다'로 남기기"

**관련 요구사항 ID**: BLOG-08, SOC-01, AUTH-13, SEC-03, SEC-07, SEC-12, BLOG-16

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 방문자 댓글 비밀번호를 맞혀 지울 수 없다 (Priority: P1)

방문자가 이름·비밀번호로 단 댓글(또는 답글)은 같은 비밀번호를 아는 사람만 지울 수 있다.
지금은 비밀번호가 주소에 실려 기록에 남고, 틀려도 제한 없이 계속 시도할 수 있어 남의 댓글을
추측으로 지울 수 있다. 앞으로는 비밀번호가 주소·기록에 남지 않고, 여러 번 틀리면 잠시 막힌다.

**Why this priority**: 지금 상태는 헌법 원칙 I(비밀번호는 주소에 노출 금지)과 기술·보안 제약
(비밀번호 입구마다 횟수 제한 또는 지연)을 직접 어긴다. 로그인 없이 누구나 시도할 수 있는
유일한 비밀번호 입구라 가장 먼저 막아야 한다.

**Independent Test**: 방문자로 댓글을 단 뒤 다른 브라우저에서 틀린 비밀번호로 5번 삭제를
시도하면 6번째부터 맞는 비밀번호로도 거절되고, 서버 접속 기록·브라우저 방문 기록 어디에도
비밀번호가 남지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 방문자 댓글이 있고, **When** 맞는 비밀번호로 삭제하면, **Then** 지금과 같이
   삭제되고(답글이 있으면 "삭제된 댓글입니다"로 남음) 비밀번호는 요청 주소에 나타나지 않는다.
2. **Given** 방문자 댓글이 있고, **When** 같은 댓글에 같은 접속 주소(IP)에서 15분 안에
   비밀번호를 5번 틀리면, **Then** 이후 시도는 맞는 비밀번호여도 "비밀번호를 여러 번 틀렸어요.
   N분 뒤에 다시 시도해 주세요"로 거절되고, 첫 실패 15분 뒤 풀린다.
3. **Given** 비밀번호를 틀린 요청이 들어오면, **When** 서버가 거절할 때, **Then** 응답은
   0.5초 이상 늦게 오고 문구는 "비밀번호가 맞지 않아요"로 같다(댓글 존재 여부 외 정보 없음).
4. **Given** 한 댓글이 잠겼을 때, **When** 블로그 주인·관리자·회원 작성자가 그 댓글을
   지우면, **Then** 잠금과 관계없이 지금처럼 삭제된다.
5. **Given** 예전 방식(주소에 비밀번호)으로 삭제 요청을 보내면, **Then** 서버는 거절하고
   비밀번호를 확인하지 않는다.

### User Story 2 - 로그아웃 표는 그 회원만, 한 번만 쓸 수 있다 (Priority: P2)

블로그에서 로그아웃하면 회원 페이지(PHP)도 함께 로그아웃된다(AUTH-13). 지금은 로그인하지
않은 사람도 로그아웃 표를 받을 수 있고, 표가 1분 동안 여러 번 쓰여서 그 링크를 남에게
보내 누르게 하면 그 사람의 회원 페이지가 로그아웃된다. 앞으로 표는 로그아웃한 회원 본인에게만
의미가 있고 한 번만 쓰인다.

**Why this priority**: 계정 탈취는 아니지만 남의 로그인을 강제로 끊을 수 있어 헌법 원칙 III
(상태를 바꾸는 표는 1회용, 링크 클릭만으로 상태가 바뀌면 안 됨)을 어긴다.

**Independent Test**: 회원 A가 블로그에서 로그아웃할 때 생긴 표를 회원 B의 브라우저에서
쓰면 B의 회원 페이지 로그인이 유지되고, A의 표를 두 번째로 쓰면 무시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 회원 A가 블로그와 회원 페이지에 모두 로그인돼 있고, **When** 블로그에서
   로그아웃하면, **Then** 지금처럼 두 곳 모두 로그아웃되고 블로그 홈으로 돌아온다.
2. **Given** 블로그에 로그인하지 않은 사람이, **When** 로그아웃 표를 달라고 요청하면,
   **Then** 표가 발급되지 않는다.
3. **Given** 회원 A의 표가 있고, **When** 회원 페이지에 회원 B로 로그인된 브라우저에서
   그 표를 쓰면, **Then** B는 로그아웃되지 않는다.
4. **Given** 회원 A의 표가 한 번 쓰였고, **When** 1분 안에 같은 표를 다시 쓰면,
   **Then** 아무 일도 일어나지 않는다.
5. **Given** 관리자·연결 안 한 예전 블로그 계정(회원 페이지 계정이 없음)이, **When**
   블로그에서 로그아웃하면, **Then** 블로그만 로그아웃되고 오류 없이 블로그 홈으로 돌아온다.
6. **Given** 회원 서버가 1.5초 안에 응답하지 않으면, **Then** 지금처럼 블로그만 로그아웃된다.

### User Story 3 - 탈퇴한 회원의 댓글에 달린 답글이 사라지지 않는다 (Priority: P3)

관리자가 회원을 탈퇴시키면 그 회원의 블로그·글·댓글이 지워진다(BLOG-16). 지금은 그 회원이
남의 글에 단 댓글에 다른 사람의 답글이 있어도 댓글이 바로 지워져, 남은 답글이 글 화면에는
안 보이면서 댓글 수·최근 댓글·블로그 관리 댓글 목록에는 남는다. 앞으로는 일반 삭제와 똑같이
"삭제된 댓글입니다" 자리로 남아 답글이 그대로 보인다.

**Why this priority**: 보안 문제는 아니지만 다른 회원이 쓴 답글이 보이지 않게 되고 숫자가
어긋나는 데이터 일관성 버그다(헌법 원칙 IV).

**Independent Test**: 회원 X가 회원 Y의 글에 댓글을 달고 Z가 답글을 단 뒤 관리자가 X를
탈퇴시키면, Y의 글에 "삭제된 댓글입니다" 아래 Z의 답글이 보이고 댓글 수가 1로 표시되는지
확인한다.

**Acceptance Scenarios**:

1. **Given** 탈퇴할 회원의 댓글에 다른 사람의 답글이 있고, **When** 관리자가 탈퇴시키면,
   **Then** 그 댓글은 이름·내용이 비워진 "삭제된 댓글입니다"로 남고 답글은 그대로 보인다.
2. **Given** 탈퇴할 회원의 댓글에 답글이 없거나 답글이 모두 같은 회원 것이면, **When**
   탈퇴시키면, **Then** 댓글과 답글 모두 지워지고 자리도 남지 않는다.
3. **Given** 탈퇴 처리가 끝났을 때, **Then** 글 화면의 댓글 수·블로그 홈의 최근 댓글·글
   주인의 블로그 관리 댓글 목록이 글 화면에 보이는 댓글과 일치한다(삭제된 댓글 자리는 셈하지
   않음).
4. **Given** 이미 예전 방식으로 탈퇴 처리돼 부모 댓글 없이 남은 답글이 있으면, **When**
   이 기능이 적용된 서버를 처음 켜면, **Then** 그 답글들은 "삭제된 댓글입니다" 자리 아래로
   다시 보이거나 정리되어 숫자가 일치한다.

---

### Edge Cases

- 잠긴 댓글에 다른 IP에서 시도하면? → IP마다 따로 센다. 한 사람이 여러 IP를 쓰는 경우를 위해
  댓글 하나당 15분에 전체 20번 실패하면 모든 IP에서 잠근다.
- 비밀번호를 맞혀 삭제에 성공하면? → 그 댓글의 실패 기록을 지운다.
- 이미 지워진 댓글이나 없는 댓글 번호에 시도하면? → "댓글을 찾을 수 없어요"로 거절하고
  실패로 세지 않는다.
- 서버를 다시 켜면 잠금이 풀리는가? → 실패 기록은 서버를 다시 켜도 유지된다.
- 로그아웃 표가 만료(1분)된 뒤 쓰이면? → 지금과 같이 무시하고 블로그 홈으로 보낸다.
- 회원 서버의 1회용 기록이 계속 쌓이면? → 만료된 기록은 정리된다.
- 탈퇴 회원이 답글만 남긴 경우(남의 댓글에 단 답글)? → 답글은 지운다(답글에는 자리를 남기지
  않음). 그 결과 부모가 "삭제된 댓글"이고 답글이 하나도 남지 않으면 자리도 정리한다.

## Requirements *(mandatory)*

### Functional Requirements

**댓글 비밀번호 (US1)**

- **FR-001**: 방문자 댓글·답글 삭제 요청은 MUST 비밀번호를 요청 본문으로만 받는다. 주소에
  비밀번호가 실린 요청은 거절한다. (BLOG-08, SEC-12)
- **FR-002**: 시스템은 MUST 댓글별·IP별로 비밀번호 실패를 기록하고, 15분 안에 5번 틀리면
  첫 실패 15분 뒤까지 그 댓글의 비밀번호 삭제를 막는다. (SEC-03과 같은 규칙)
- **FR-003**: 시스템은 MUST 댓글 하나에 15분 안에 IP와 관계없이 20번 실패하면 모든 IP에서
  같은 방식으로 막는다.
- **FR-004**: 틀린 비밀번호 응답은 MUST 0.5초 이상 늦추고, 잠금 중에는 남은 시간을 분 단위로
  알려 준다.
- **FR-005**: 비밀번호 삭제에 성공하면 MUST 그 댓글의 실패 기록을 지운다.
- **FR-006**: 블로그 주인·관리자·회원 작성자의 삭제는 MUST 잠금의 영향을 받지 않는다.

**로그아웃 표 (US2)**

- **FR-007**: 로그아웃 표는 MUST 블로그에 로그인한 회원 계정(회원 페이지와 연결된 계정)에만
  발급하고, 그 회원 번호를 서명 안에 담는다. (AUTH-13, SEC-07)
- **FR-008**: 회원 서버는 MUST 표의 회원 번호가 지금 회원 페이지에 로그인된 회원과 같을 때만
  로그아웃한다. 다르거나 로그인돼 있지 않으면 로그아웃하지 않는다.
- **FR-009**: 회원 서버는 MUST 쓰인 표를 기록해 만료 전 재사용을 거절한다(1회용).
- **FR-010**: 관리자·연결 안 한 예전 블로그 계정의 로그아웃은 MUST 표 없이 블로그만
  로그아웃한다.
- **FR-011**: 지금의 동작(1분 만료, 1.5초 응답 없으면 블로그만 로그아웃, 블로그 홈 복귀,
  위조 표 거절)은 MUST 유지한다.

**탈퇴 회원 댓글 (US3)**

- **FR-012**: 관리자 회원 탈퇴는 MUST 그 회원의 댓글 중 다른 사람의 답글이 남는 댓글을
  일반 삭제와 같은 "삭제된 댓글입니다" 자리로 바꾼다(이름·내용·비밀번호 비움). (BLOG-16, SOC-01)
- **FR-013**: 탈퇴 회원의 답글과, 남는 답글이 없는 댓글은 MUST 지운다. 그 결과 답글이 하나도
  없는 "삭제된 댓글" 자리는 정리한다.
- **FR-014**: 댓글 수·최근 댓글·블로그 관리 댓글 목록은 MUST 글 화면에 실제로 보이는 댓글과
  같은 기준으로 센다.
- **FR-015**: 서버를 켤 때 MUST 부모 없이 남은 답글을 한 번 찾아 정리해 기존 데이터의
  숫자를 맞춘다(기존 글·다른 댓글은 건드리지 않음). (헌법 원칙 IV)

**공통**

- **FR-016**: 모든 새 거절 문구는 MUST 한국어로 다음 행동을 알려 준다.
- **FR-017**: 구현이 끝나면 MUST requirements.md의 BLOG-08·AUTH-13·SEC-03·BLOG-16 완료
  기준과 7·8장 남은 과제 체크를 갱신한다. (헌법 원칙 V)

### Key Entities

- **댓글 비밀번호 실패 기록**: 어느 댓글에, 어느 접속 주소(IP)에서, 언제 틀렸는지. 15분이
  지나거나 삭제에 성공하면 의미가 없어진다.
- **로그아웃 표**: 회원 번호, 만료 시각, 1회용 번호를 서명으로 묶은 것. 블로그가 만들고
  회원 서버가 확인한다.
- **쓰인 로그아웃 표 기록**: 회원 서버가 1회용 번호를 만료 시각까지 보관한다.
- **댓글(기존)**: "삭제된 댓글" 상태와 부모 댓글 관계를 이미 가진다. 탈퇴 처리도 이 상태를
  쓴다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 한 방문자 댓글의 비밀번호를 한 IP에서 15분 동안 맞히려 할 때 시도할 수 있는
  횟수가 5번 이하다(지금은 무제한).
- **SC-002**: 댓글 삭제 후 서버 접속 기록과 브라우저 방문 기록 어디에서도 비밀번호 문자열이
  0건 발견된다.
- **SC-003**: 다른 회원의 로그아웃 표나 이미 쓴 표로 회원 페이지 로그아웃에 성공하는 경우가
  0건이다.
- **SC-004**: 정상 로그아웃은 지금과 같이 한 번 누르면 두 곳 모두 로그아웃되고, 걸리는 시간이
  체감상 늘지 않는다(회원 서버 정상 시 2초 이내).
- **SC-005**: 탈퇴 처리 후 모든 글에서 "글 화면에 보이는 댓글 수"와 "목록·관리 화면의 댓글 수"가
  100% 일치한다.
- **SC-006**: 기존 blog.db로 서버를 켰을 때 글·댓글·로그인이 그대로 유지되고, 이미 생긴
  부모 없는 답글 문제도 정리된다.

## Assumptions

- 잠금 규칙(15분·5번·첫 실패 15분 뒤 해제)은 회원 로그인(SEC-03)과 같게 맞춘다. 댓글당 IP
  전체 20번 상한은 여러 IP 우회를 막기 위한 기본값이다.
- 잠금은 "그 댓글을 비밀번호로 지우는 것"만 막는다. 같은 방문자가 새 댓글을 쓰는 것은 막지
  않는다.
