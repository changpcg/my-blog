**Created**: 2026-10-07

**Status**: Implemented (2026-10-07)

**Input**: User description: "requirements.md 7장 남은 과제 중 회원 계정 관련 3건 — 회원 페이지(PHP)에 닉네임·자기소개·비밀번호 바꾸기 화면 만들기, 사이트 설정의 '회원가입 허용' 끄기를 회원 서버에도 적용, 회원 탈퇴를 회원 서버(PHP)까지 적용"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 회원 페이지에서 내 정보를 바꾼다 (Priority: P1)

회원은 회원 페이지(PHP) 내 정보에서 닉네임·자기소개·비밀번호를 바꾼다. 지금은 보기만 되는데 블로그 내 정보는
"비밀번호와 자기소개는 회원 페이지에서 관리해요"라고 안내해, 회원이 안내를 따라가도 바꿀 곳이 없다.

**Why this priority**: 사용자에게 약속한 기능이 없는 상태라 가장 먼저 채워야 한다. 다른 두 스토리와 독립적이다.

**Independent Test**: 회원으로 회원 페이지 내 정보 → 수정에서 닉네임·자기소개·비밀번호를 바꾸고, 새 비밀번호로 다시
로그인되는지, 블로그 닉네임이 다음 블로그 입장 때 바뀌는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 아이디·비밀번호 회원이 로그인해 있고, **When** 내 정보 수정에서 닉네임(2~20자)·자기소개(300자 이하)를
   바꾸면, **Then** 회원 페이지에 바로 보이고 다음에 블로그로 들어갈 때 블로그 닉네임도 같은 값으로 바뀐다.
2. **Given** 아이디·비밀번호 회원이, **When** 현재 비밀번호를 맞게 넣고 새 비밀번호(영문+숫자 8자 이상, 72바이트 이하)와
   확인을 같게 넣으면, **Then** 비밀번호가 바뀌고 다른 브라우저의 회원 페이지 로그인은 끊긴다.
3. **Given** 현재 비밀번호가 틀리면, **Then** 바뀌지 않고, 이 확인도 회원 로그인과 같은 잠금 규칙(15분 5번)을 따른다.
4. **Given** SNS로만 가입한 회원이, **When** 내 정보 수정을 열면, **Then** 닉네임·자기소개는 바꿀 수 있고 비밀번호는
   "처음 비밀번호 만들기"(현재 비밀번호 없이)로 만들 수 있다. 만들면 아이디·비밀번호 로그인도 된다.
5. **Given** 블로그 내 정보에서 닉네임을 바꾼 경우, **Then** 지금처럼 블로그 닉네임만 바뀌고 회원 페이지 닉네임은 그대로다
   (회원 페이지 닉네임은 블로그를 처음 만들 때와 회원 페이지에서 바꿀 때만 블로그로 전달된다).

### User Story 2 - '회원가입 허용'을 끄면 회원 서버 가입도 막힌다 (Priority: P2)

관리자가 블로그 사이트 설정에서 회원가입 허용을 끄면, 지금은 블로그의 가입 버튼만 숨고 회원 서버(PHP) 가입·SNS 가입은
그대로 된다. 앞으로는 회원 서버의 새 가입도 막힌다. 이미 가입한 회원의 로그인은 막지 않는다.

**Why this priority**: 공개 전 스팸 가입을 막는 유일한 스위치가 반쪽짜리라 관리자 기대와 다르게 동작한다.

**Independent Test**: 관리자가 허용을 끈 뒤 회원 서버 회원가입 화면·SNS 처음 가입·아이디 중복 확인을 시도하면 모두
"지금은 새 가입을 받지 않아요"로 거절되고, 기존 회원 로그인은 되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 회원가입 허용이 꺼져 있고, **When** 회원 서버 회원가입 화면을 열거나 가입을 보내면, **Then** 가입 폼 대신
   "지금은 새 가입을 받지 않아요" 안내가 보이고 서버도 가입을 거절한다.
2. **Given** 허용이 꺼져 있고, **When** 처음 보는 SNS 계정으로 로그인하면, **Then** SNS 가입 화면으로 가지 않고 같은 안내가
   보인다. 이미 연결된 SNS 계정은 로그인된다.
3. **Given** 허용이 꺼져 있고, **When** 기존 회원이 아이디·비밀번호로 로그인하면, **Then** 로그인된다.
4. **Given** 관리자가 허용을 다시 켜면, **Then** 1분 안에 회원 서버 가입이 다시 열린다.
5. **Given** 회원 서버가 블로그 설정을 확인할 수 없으면(블로그가 꺼짐 등), **Then** 마지막으로 확인한 값을 쓰고, 한 번도
   확인하지 못했으면 가입을 막는다(안전한 쪽).

---

### User Story 3 - 탈퇴하면 회원 서버 계정도 함께 지워진다 (Priority: P3)

관리자가 회원을 탈퇴시키면 지금은 블로그 계정만 지워지고 회원 서버 계정·SNS 연결은 남아, 가입 허용이 켜져 있으면 그
회원이 다시 로그인할 때 빈 블로그가 새로 생긴다. 앞으로는 회원 서버 계정과 SNS 연결도 함께 지워지고, 회원 스스로도
회원 페이지에서 탈퇴할 수 있다.

**Why this priority**: 탈퇴 후 다시 생기는 빈 블로그는 혼란을 주지만 보안 사고는 아니라 P3로 둔다.

**Independent Test**: 관리자가 회원 X를 탈퇴시키면 X는 회원 서버에도 로그인할 수 없고 SNS 연결도 사라지며, 회원 Y가
회원 페이지에서 스스로 탈퇴하면 블로그 계정·글까지 함께 정리되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 블로그 계정이 회원 서버 계정과 연결돼 있고, **When** 관리자가 탈퇴시키면, **Then** 블로그 쪽 정리(001 이후
   규칙)와 함께 회원 서버 계정·SNS 연결·로그인 실패 기록이 지워지고, 그 회원의 회원 페이지 로그인도 끊긴다.
2. **Given** 회원이 회원 페이지 내 정보에서 "탈퇴하기"를 누르고 비밀번호(SNS 전용 회원은 아이디 입력)로 확인하면,
   **Then** 회원 서버 계정과 연결된 블로그 계정·글·댓글이 관리자 탈퇴와 같은 규칙으로 지워진다.
3. **Given** 회원 서버나 블로그 중 한쪽이 꺼져 있어 함께 지울 수 없으면, **Then** 탈퇴를 진행하지 않고 "잠시 뒤 다시
   시도해 주세요"로 안내한다(한쪽만 지워진 상태를 만들지 않음).
4. **Given** 관리자 계정(admin)이나 회원 서버와 연결되지 않은 예전 블로그 계정이면, **Then** 지금처럼 블로그만 처리한다.
5. **Given** 탈퇴한 회원의 아이디는, **Then** 다른 사람이 새로 가입할 수 있다(회원 번호는 재사용되지 않음).

---

### Edge Cases

- 회원 DB(php-auth/db)를 새로 만들어 회원 번호가 1부터 다시 시작하면? → 블로그는 회원 번호와 함께 가입 시각을 비교해,
  다르면 예전 블로그에 붙이지 않고 거절·안내한다(남의 블로그로 들어가는 문제 차단).
- 닉네임을 바꾼 직후 블로그에 이미 로그인해 있으면? → 다음 입장 때 반영된다. 즉시 반영은 범위 밖.
- 비밀번호를 바꾼 회원의 블로그 로그인(2주)은? → 유지한다. 회원 페이지 로그인만 다른 브라우저에서 끊긴다.
- 탈퇴 확인 중 비밀번호를 여러 번 틀리면? → 로그인과 같은 잠금.
- 회원가입 허용이 꺼진 상태에서 아이디 중복 확인 요청은? → 가입과 같이 거절한다.

## Requirements *(mandatory)*

### Functional Requirements

**정보 수정 (US1)**

- **FR-001**: 회원 서버는 MUST 로그인한 회원에게 닉네임·자기소개·비밀번호를 바꾸는 화면을 제공한다. 아이디는 바꿀 수 없다. (AUTH-16)
- **FR-002**: 입력 규칙은 MUST 가입 규칙(AUTH-01)과 같고, 서버가 다시 검사한다.
- **FR-003**: 비밀번호 변경은 MUST 현재 비밀번호 확인(SNS 전용 회원의 첫 비밀번호는 제외)과 로그인 잠금 규칙을 따르고, 성공 시 그 회원의 다른 회원 페이지 세션을 끊는다. (SEC-02, SEC-03)
- **FR-004**: 회원 페이지에서 바꾼 닉네임은 MUST 다음 블로그 입장 때 블로그 닉네임에 반영된다. (AUTH-08, BLOG-15)
- **FR-005**: 모든 변경 폼은 MUST CSRF 토큰을 확인한다. (SEC-05)

**가입 허용 (US2)**

- **FR-006**: 회원 서버는 MUST 블로그의 '회원가입 허용' 값을 서명된 방법으로 확인해, 꺼져 있으면 일반 가입·SNS 첫 가입·아이디 중복 확인을 거절한다. (AUTH-14)
- **FR-007**: 확인 결과는 최대 1분 동안 재사용할 수 있고, 확인할 수 없으면 마지막 값, 그것도 없으면 '꺼짐'으로 본다.
- **FR-008**: 기존 회원의 로그인·이미 연결된 SNS 로그인은 MUST 허용 값과 관계없이 된다.

**탈퇴 (US3)**

- **FR-009**: 관리자 탈퇴와 회원 스스로 탈퇴는 MUST 블로그 계정과 회원 서버 계정(+SNS 연결·로그인 실패 기록)을 함께 지운다. (BLOG-16)
- **FR-010**: 두 서버 사이 탈퇴 요청은 MUST sso.key 서명·만료·1회용을 갖추고, 한쪽이 실패하면 다른 쪽도 지우지 않는다. (헌법 III·IV)
- **FR-011**: 회원 스스로 탈퇴는 MUST 비밀번호(SNS 전용 회원은 아이디 재입력) 확인과 CSRF를 거친다.
- **FR-012**: 블로그는 MUST 입장권의 회원 번호와 회원 가입 시각이 블로그에 저장된 값과 다르면 기존 블로그에 연결하지 않는다.

**공통**

- **FR-013**: 새 화면·문구는 MUST 한국어, 회원 화면 디자인 규칙(NFR-01·NFR-04)을 따른다.
- **FR-014**: 구현 후 MUST requirements.md와 원본 문서의 AUTH-14·AUTH-15·AUTH-16·BLOG-16과 7장 남은 과제를 갱신한다.

### Key Entities

- **회원(회원 서버)**: 아이디·닉네임·자기소개·비밀번호 해시·가입 시각. 수정·삭제 대상.
- **블로그 계정**: 회원 번호(auth_uid)에 더해 회원 가입 시각을 기억해 번호 재사용을 구분한다.
- **가입 허용 값**: 블로그 settings의 allow_signup. 회원 서버는 서명된 응답으로 읽고 잠시 기억한다.
- **탈퇴 요청**: 회원 번호·만료·1회용 번호를 서명으로 묶은 서버 간 요청.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 회원이 회원 페이지에서 닉네임·자기소개·비밀번호를 각각 1분 안에 바꿀 수 있다.
- **SC-002**: 회원가입 허용이 꺼진 동안 회원 서버에서 새로 생기는 계정이 0개다(일반·SNS 모두).
- **SC-003**: 탈퇴 후 그 회원으로 회원 페이지·블로그 어디에도 로그인되지 않고, 빈 블로그가 다시 생기는 경우가 0건이다.
- **SC-004**: 탈퇴 도중 한쪽 서버가 꺼져 있어도 한쪽만 지워진 계정이 0건이다.
- **SC-005**: 회원 DB를 새로 만든 뒤 같은 번호의 새 회원이 예전 블로그에 들어가는 경우가 0건이다.

## Assumptions

- 두 서버는 같은 컴퓨터(또는 같은 네트워크)에서 돌고, 서버끼리 HTTP로 서로 부를 수 있다(AUTH_URL·BLOG_URL).
- 회원 스스로 탈퇴는 블로그 내 정보가 아니라 회원 페이지에서만 시작한다(계정의 주인이 회원 서버이므로).
- 올린 파일 처리는 001 이후 관리자 탈퇴 규칙(다른 곳에서 안 쓰면 삭제)을 그대로 따른다.
- 블로그 내 정보의 닉네임 변경(AUTH-15)은 블로그 안에서만 적용되는 지금 동작을 유지한다.
- 이메일·비밀번호 찾기는 회원 정보에 이메일이 없어 범위 밖이다.
