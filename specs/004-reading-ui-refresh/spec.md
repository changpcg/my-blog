# Feature Specification: 담백한 디자인과 읽기 좋은 글 화면

**Feature Branch**: `004-reading-ui-refresh`

**Created**: 2026-10-08

**Status**: Implemented (2026-10-08)

글 목록 대표 사진, 글 읽기 도구, 글 아래 영역, 사진·코드 보기 / 디자인 방향: 티스토리처럼 담백하게

**관련 요구사항 ID**: NFR-01(개정), NFR-03(개정), NFR-04, NFR-10(개정), BLOG-01(개정), BLOG-05(개정), BLOG-06, BLOG-09(개정),
SOC-02, SOC-03(개정), SEC-04(개정), SEC-12 / 새 ID: BLOG-20(글 목록 대표 사진), BLOG-21(읽기 도구), BLOG-22(글 아래 영역), BLOG-23(사진·코드 보기)

**조사 근거**: 티스토리 공지 블로그(글 위 카테고리·제목·작성자·날짜, 좋아요·공유하기·구독하기 줄, 같은 카테고리 글 4개 사진 카드,
작성자 박스, 본문 16px·줄 간격 1.75, 얇은 구분선과 넉넉한 여백), velog(제목 아래 태그, 넓은 화면의 목차, 이전·다음 글),
네이버 블로그(목록 오른쪽 대표 사진, 공감·댓글 수, 같은 카테고리 다른 글, 이웃 추가). 지금 우리 블로그는 PC에서 3px 테두리 +
진한 그림자 카드, 글 카드에 사진이 위에 크게 붙거나 없음, 목차·읽는 시간·공유·사진 크게 보기·코드 복사 없음, 관련 글은 글자 목록,
375px에서 긴 코드가 있으면 화면이 옆으로 넘침(479px).

## Clarifications

### Session 2026-10-08

- Q: 이번에 어떤 화면을 고칠까? → A: 네 가지 모두 — 글 목록 대표 사진, 글 읽기 도구(목차·읽는 시간·진행 막대·맨 위로),
  글 아래 영역(공유·작성자 카드·관련 글 사진 카드·이전/다음 글), 사진·코드 보기(크게 보기·코드 복사)
- Q: 디자인 방향은? → A: 티스토리처럼 담백하게 — 굵은 테두리·진한 그림자를 걷어 내고 얇은 선과 여백 위주로
  (네오 브루탈리즘 NFR-01과 헌법 VI의 디자인 문구를 바꿈)
- 375px 가로 넘침은 고를 것 없이 함께 고친다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 사이트 전체가 담백한 디자인으로 바뀐다 (Priority: P1)

방문자는 굵은 테두리와 진한 그림자 대신 얇은 선과 넉넉한 여백으로 정리된 화면을 본다. 블로그 화면과 회원 화면(로그인·가입·내 정보)이
같은 분위기다. 다크 모드, 키보드 포커스 표시, '동작 줄이기'는 지금처럼 동작한다.

**Why this priority**: 사용자가 고른 방향이자 다른 모든 개선이 올라갈 바탕이다.

**Independent Test**: 홈·개인 블로그·글 보기·블로그 관리·사이트 설정·회원 로그인 화면을 라이트·다크, PC·375px로 열어 굵은 테두리와
진한 그림자가 남아 있지 않은지, 글자·버튼이 읽히는지 본다.

**Acceptance Scenarios**:

1. **Given** 어떤 화면이든, **When** 카드·위젯·버튼을 보면, **Then** 테두리는 얇은 선이고 진한 그림자가 없다. 마우스를 올렸을 때도
   튀어나오는 움직임 없이 선 색·옅은 그림자 정도로만 바뀐다.
2. **Given** 다크 모드, **Then** 모든 새 요소가 어두운 바탕에 맞는 색으로 보인다(NFR-04).
3. **Given** 키보드로 이동하면, **Then** 지금처럼 강조색 포커스 테두리가 보인다(NFR-10).
4. **Given** 회원 화면(PHP), **Then** 블로그와 같은 색·선·둥글기로 보인다.

---

### User Story 2 - 글 목록에서 대표 사진을 보며 글을 고른다 (Priority: P1)

방문자는 홈·개인 블로그·태그·검색·이웃 새 글 목록에서 글을 한 줄씩 본다. 사진이 있는 글은 오른쪽에 첫 사진이 작게 보이고, 사진이 없는
글은 글자만 보인다(티스토리·네이버 방식). 휴대폰에서도 같은 모양으로 한 화면에 더 많은 글을 볼 수 있다.

**Why this priority**: 블로그 첫인상과 글 고르기를 가장 크게 바꾼다.

**Independent Test**: 사진이 있는 글과 없는 글이 섞인 목록을 PC·375px로 열어 사진 위치와 크기, 글 정보(종류·카테고리·제목·요약·
블로그·날짜·댓글·조회·공감)가 빠짐없이 보이는지 본다.

**Acceptance Scenarios**:

1. **Given** 본문에 이 블로그에 올린 사진이 있는 글, **When** 목록을 보면, **Then** 첫 사진이 오른쪽 정사각형 대표 사진으로 보이고
   (가운데 기준으로 잘림), 사진이 늦게 오면 자리만 잡혀 있다.
2. **Given** 사진이 없는 글, **Then** 빈 자리 없이 글자가 줄 끝까지 쓴다.
3. **Given** 휴대폰(375px), **Then** 대표 사진은 작아지고 요약은 2줄까지, 날짜·댓글·조회 줄은 사진 아래까지 한 줄로 넓게 쓴다.
4. **Given** 자주 묻는 질문·용어 사전 목록, **Then** 지금처럼 펼치기 목록·색인으로 보인다(이번 변경 밖, 카드 모양만 새 디자인).

### User Story 3 - 긴 글을 편하게 읽는다 (Priority: P1)

독자는 글 맨 위에서 몇 분이면 읽을지 보고, 소제목이 둘 이상인 글은 목차를 눌러 원하는 부분으로 바로 간다. 읽는 동안 화면 맨 위의
얇은 막대가 얼마나 읽었는지 보여 주고, 한참 내려가면 '맨 위로' 버튼이 나타난다. 휴대폰에서 긴 코드·넓은 표가 있어도 화면이 옆으로
넘치지 않고 코드·표 안에서만 옆으로 밀린다.

**Why this priority**: 블로그의 본업(읽기)이고, 375px 넘침은 지금 요구사항(NFR-03)을 어기는 버그다.

**Independent Test**: 소제목·긴 코드·표가 있는 글을 PC·375px로 열어 읽는 시간, 목차 이동, 진행 막대, 맨 위로 버튼, 가로 넘침 없음을 본다.

**Acceptance Scenarios**:

1. **Given** 글 보기, **Then** 제목 아래 날짜·조회 옆에 "N분 읽기"가 보인다(1분 미만은 1분).
2. **Given** 소제목(h2·h3)이 2개 이상인 글, **When** 목차의 항목을 누르면, **Then** 그 소제목이 위쪽 고정 바 바로 아래로 오도록
   부드럽게 이동한다('동작 줄이기'면 바로 이동). 주소는 바뀌지 않고 뒤로 가기가 꼬이지 않는다. 소제목이 1개 이하면 목차가 없다.
3. **Given** 휴대폰·태블릿(900px 이하), **Then** 목차는 접힌 상태로 시작하고 눌러서 펼친다. 넓은 화면에서는 펼친 상태로 시작한다.
4. **Given** 글을 읽어 내려가면, **Then** 화면 맨 위 얇은 막대가 본문을 읽은 비율만큼 찬다.
5. **Given** 한 화면 넘게 내려가면, **Then** 오른쪽 아래에 '맨 위로' 버튼이 나타나고 누르면 맨 위로 가며 포커스는 글 제목으로 간다.
6. **Given** 375px에서 긴 코드 줄·넓은 표가 있는 글, **Then** 페이지 전체 가로 스크롤이 생기지 않고, 표 칸의 글자가 한 글자씩 끊기지 않는다.

### User Story 4 - 다 읽은 뒤 다음 글로 이어진다 (Priority: P2)

독자는 글 아래에서 공감과 함께 '공유하기'로 주소를 보내고, 작성자 카드에서 바로 이웃 추가를 하며, 같은 카테고리의 다른 글을 사진 카드로
보고, 이전·다음 글로 넘어간다.

**Why this priority**: 체류와 재방문을 늘리지만 읽기 자체보다는 뒤다.

**Independent Test**: 같은 카테고리 글이 여러 개인 블로그에서 글을 열어 공유·이웃 추가·관련 글 카드·이전/다음 카드를 눌러 본다.

**Acceptance Scenarios**:

1. **Given** 글 아래, **When** '공유하기'를 누르면, **Then** 공유 창이 있는 기기에서는 공유 창이, 없으면 글 주소가 복사되고
   "주소를 복사했어요"가 보인다. 복사도 안 되면 주소 칸과 "직접 복사해 주세요" 안내가 나온다.
2. **Given** 작성자 카드, **Then** 블로그 이름·닉네임·글 수·이웃 수·소개와 '이웃 추가'(내 블로그면 없음, 방문자는 로그인 안내, 서버 규칙은
   SOC-03 그대로)와 '블로그 가기'가 있다. 이웃을 추가하면 위쪽 작은 배너의 버튼·이웃 수도 함께 바뀐다.
3. **Given** 같은 블로그·같은 종류·같은 카테고리의 다른 글, **Then** 지금 사용자가 볼 수 있는 글 최신순 최대 4개가 사진 카드로 보인다
   (사진이 없으면 종류 아이콘이 있는 빈 카드). 비공개 글은 볼 수 있는 사람(글쓴이·관리자)에게만.
4. **Given** 이전·다음 글이 있으면, **Then** 카드 두 개로 나란히(휴대폰은 위아래) 보인다. 둘 다 없으면 칸 자체가 없다.

---

### User Story 5 - 사진과 코드를 자세히 본다 (Priority: P3)

독자는 본문 사진을 눌러 화면 가득 크게 보고, 코드 블록 위에서 언어 이름을 보고 '복사'로 코드를 바로 가져간다.

**Why this priority**: 있으면 좋은 편의 기능이다.

**Independent Test**: 사진과 코드가 있는 글에서 사진 크게 보기(열기·닫기: 바깥 누르기·Esc·닫기 버튼, 키보드로 열기)와 코드 복사를 해 본다.

**Acceptance Scenarios**:

1. **Given** 본문 사진, **When** 누르면(키보드로는 Enter), **Then** 어두운 배경 위에 화면 크기에 맞춘 사진과 설명(대체 글)이 뜨고,
   바깥·닫기 버튼·Esc로 닫히며 닫히면 포커스가 원래 사진으로 돌아간다. 열려 있는 동안 뒤쪽 화면은 스크롤·포커스되지 않는다.
2. **Given** 코드 블록, **Then** 위쪽 줄에 언어 이름(글쓴이가 적은 것, 없으면 "코드")과 '복사' 버튼이 있고, 누르면 코드가 복사되고
   "복사했어요"로 잠시 바뀐다. 복사가 안 되면 "복사하지 못했어요" 안내가 나온다.
3. **Given** 링크가 걸린 사진·첨부 파일 카드·용어 사전 정의 같은 기존 본문 꾸밈, **Then** 지금처럼 동작한다.

---

### Edge Cases

- 목록 사진 주소가 깨졌으면? → 사진 칸을 숨기고 글자만 보인다(빈 네모 없이). 관련 글 카드는 종류 아이콘으로 바뀐다.
- 본문 첫 사진이 외부 주소면? → 대표 사진으로는 이 블로그에 올린 사진(/uploads/의 사진 형식)만 쓴다(외부 추적 사진 차단).
  외부 사진 뒤에 올린 사진이 있으면 그 올린 사진을 쓴다. 본문 안 표시는 지금 규칙 그대로.
- 코드 블록 안에 사진 문법이 예시로 들어 있으면? → 대표 사진으로 쓰지 않는다.
- 소제목이 아주 많은 글? → 목차는 h2·h3만, 길면 목차 상자 안에서 스크롤.
- 같은 이름의 소제목이 여러 개? → 순서로 구분해 각각 정확히 이동한다.
- 클립보드를 쓸 수 없는 환경(https가 아닌 다른 기기 주소 등)? → 예전 방식 복사를 한 번 더 시도하고, 그래도 안 되면 직접 복사 안내.
- 사진을 크게 본 채로 뒤로 가기·다른 글로 이동하면? → 크게 보기가 닫힌다.
- FAQ·용어 사전 글? → 읽는 시간·목차·진행 막대 규칙은 같되, 소제목이 없으면 목차 없음.
- 관련 글이 없으면? → 관련 글 칸 자체가 없다.
- 미니룸 그림·날씨·주식 위젯? → 그림은 그대로, 위젯 테두리·그림자만 새 규칙.
- 글쓰기 미리보기? → 본문과 같은 모양(코드 머리·사진 크게 보기)으로 보인다.
- 본문이 아주 길거나 같은 기호(`<img `, `![` 등)를 수십만 번 되풀이하면? → 본문은 20만 자까지만 저장되고, 대표 사진·요약 계산은 길이에 비례하는
  시간 안에 끝나 다른 방문자의 화면이 멈추지 않는다(검토에서 찾은 문제: 고치기 전에는 10만 자 본문 하나로 목록이 16초 멈춤).
- 글 속 HTML이 화면 부품 이름(`id="shareUrl"`, `class="code-copy"`, `data-nb` 등)을 쓰거나 코드 칸을 숨기면? → 무시된다. 글 속 id는 접두어가
  붙고, data-* 속성과 글쓴이 class(코드 언어 표시 제외)는 없어지며, 복사 버튼이 붙는 코드 칸은 숨길 수 없다.
- 글을 불러오는 사이 다른 화면으로 가면? → 늦게 온 글은 그리지 않는다(진행 막대가 다른 화면에 남지 않음).

## Requirements *(mandatory)*

### Functional Requirements

**디자인 (US1)**

- **FR-001**: 사이트의 모든 카드·위젯·버튼·입력 칸은 MUST 얇은 선(1px)·둥근 모서리·진한 그림자 없음 규칙을 따르고, 마우스를 올렸을 때
  위치를 움직이지 않는다. 떠 있는 메뉴(내 메뉴)만 옅은 그림자를 쓴다. (NFR-01 개정)
- **FR-002**: 회원 화면(PHP)은 MUST 블로그와 같은 색·선·둥글기 규칙을 따른다. (NFR-01 개정)
- **FR-003**: 새 요소는 MUST 라이트·다크 모드에서 읽히고, 키보드 포커스 표시와 화면 읽기용 이름을 가지며, '동작 줄이기'면 움직임 없이
  동작한다. (NFR-04, NFR-10)

**글 목록 (US2)**

- **FR-004**: 글 목록(홈·개인 블로그·글 종류·태그·검색·이웃 새 글)은 MUST 한 줄에 글 하나, 대표 사진이 있으면 오른쪽 정사각형으로
  보인다. 자주 묻는 질문·용어 사전 목록은 지금 모양을 유지한다. (새 BLOG-20, BLOG-01 개정)
- **FR-005**: 대표 사진은 MUST 서버가 본문에서 찾은, 이 블로그에 올린 사진(/uploads/의 사진 형식) 중 첫 번째만 쓰고(마크다운·HTML 사진
  모두, 코드 블록 속 예시와 외부 주소 사진은 제외), 화면은 불러오지 못하면 사진 칸을 숨긴다. (새 BLOG-20)
- **FR-006**: 목록의 글 정보(종류·카테고리·비공개 표시·제목·요약·블로그·날짜·댓글·조회·공감)는 MUST 지금처럼 모두 보인다. 요약에는 HTML
  태그가 섞이지 않는다. (BLOG-01, SOC-02)

**읽기 도구 (US3)**

- **FR-007**: 글 보기는 MUST 제목 아래에 읽는 시간(공백을 뺀 본문 글자 수 ÷ 500, 올림, 최소 1분)을 보여 준다. (새 BLOG-21)
- **FR-008**: 소제목(h2·h3)이 2개 이상이면 MUST 본문 위에 목차를 보이고, 누르면 주소(해시)를 바꾸지 않고 그 소제목으로 이동하며 포커스도
  옮긴다. 넓은 화면은 펼침, 900px 이하는 접힘으로 시작한다. (새 BLOG-21)
- **FR-009**: 글 보기는 MUST 화면 맨 위에 본문 진행 막대를, 한 화면 넘게 내려가면 '맨 위로' 버튼을 보여 준다. 다른 화면으로 가면 둘 다
  사라진다. (새 BLOG-21)
- **FR-010**: 375px에서 MUST 긴 코드·넓은 표·큰 사진이 있어도 페이지 전체 가로 스크롤이 없고, 코드·표는 그 안에서만 옆으로 밀린다.
  (NFR-03 개정)

**글 아래 (US4)**

- **FR-011**: 공감 옆에 MUST '공유하기'가 있고, 공유 창이 있으면 그것을, 없으면 주소 복사를, 둘 다 안 되면 직접 복사 안내를 쓴다.
  (새 BLOG-22)
- **FR-012**: 작성자 카드는 MUST 블로그 이름·닉네임·글 수·이웃 수·소개·'이웃 추가'·'블로그 가기'를 보여 주고, 이웃 추가는 기존 서버
  규칙을 그대로 쓴다. (새 BLOG-22, SOC-03 개정)
- **FR-013**: 관련 글은 MUST 같은 블로그·같은 종류·같은 카테고리에서 지금 사용자가 볼 수 있는 글 최신순 최대 4개를 사진 카드로 보여 주며,
  볼 수 있는지는 서버가 정한다. (새 BLOG-22, BLOG-09 개정, SEC-12)
- **FR-014**: 이전·다음 글은 MUST 카드 두 개로 나란히(600px 이하 위아래) 보인다. (새 BLOG-22)

**사진·코드 (US5)**

- **FR-015**: 본문 사진(링크가 걸린 사진 제외)은 MUST 눌러서 크게 볼 수 있고, 바깥·닫기 버튼·Esc로 닫히며, 열려 있는 동안 포커스가 그 안에
  머물고 닫히면 원래 사진으로 돌아간다. (새 BLOG-23, NFR-10)
- **FR-016**: 코드 블록은 MUST 언어 이름과 '복사' 버튼을 보여 주고, 복사 성공·실패를 한국어로 알린다(성공은 화면 읽기 프로그램에도).
  (새 BLOG-23)

**공통**

- **FR-018**: 서버는 MUST 글 본문을 20만 자까지만 받고, 대표 사진·요약 계산은 본문 길이에 비례하는 시간 안에 끝난다(같은 기호를 되풀이한 본문으로
  서버를 멈추게 할 수 없다). (BLOG-05 개정, 헌법 I)
- **FR-019**: 글 본문 HTML은 MUST 화면 부품(공유 주소 칸·코드 복사·사진 크게 보기·이웃 버튼·알림 칸 등)을 흉내 내거나 가로챌 수 없다: 글 속
  id·name은 접두어를 붙이고, data-* 속성과 글쓴이 class(코드 언어 표시 제외)는 없애며, 복사 버튼이 붙는 코드 칸의 숨김(style·hidden)은 지운다.
  (SEC-04 개정)
- **FR-017**: 구현 후 MUST requirements.md 두 사본과 원본 문서에 BLOG-20~23을 추가하고 NFR-01·NFR-03·NFR-10·BLOG-01·BLOG-09·SOC-03
  문구를 고치며, 헌법 VI의 디자인 문구를 NFR-01을 가리키게 바꾼다. (헌법 V)

### Key Entities

- **대표 사진(thumbnail)**: 글마다 본문에서 찾은 첫 업로드 사진 주소(없으면 없음). 저장하지 않고 목록·관련 글을 줄 때 계산한다.
- **관련 글 카드**: 글 번호·제목·날짜·종류·공개 여부·대표 사진. 글 보기 응답에 최대 4개.
- **목차 항목**: 소제목 수준(2·3)·글자·본문 안 위치. 화면에서만 만든다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 바꾼 화면(홈·개인 블로그·글 보기·자주 묻는 질문·용어 사전·이웃 새 글·블로그 관리·사이트 설정·회원 로그인·가입) × 라이트·다크 ×
  PC·375px에서 오프셋 그림자·3px 테두리가 0곳이다.
- **SC-002**: 375px에서 긴 코드·넓은 표가 있는 글을 포함한 모든 화면의 페이지 가로 넘침이 0건이다.
- **SC-003**: 소제목 2개 이상인 글에서 목차 항목을 눌렀을 때 그 소제목이 고정 바 바로 아래(화면 위 100~140px)에 오는 비율이 100%이고,
  주소창의 글 주소가 바뀌지 않는다.
- **SC-004**: 목록에서 올린 사진이 있는 글은 100% 대표 사진이 보이고, 사진이 없거나 깨진 글에 빈 사진 칸이 0개다.
- **SC-005**: 공유하기·코드 복사는 지원 브라우저에서 한 번 눌러 끝나고, 실패하면 직접 복사 방법이 보인다.
- **SC-006**: 기존 기능(공감·이웃·댓글·글쓰기·관리·회원 화면) 회귀 테스트(001·002·003 스모크)가 모두 통과한다.
- **SC-007**: 같은 기호를 되풀이한 20만 자 본문이 여럿 있어도 글 목록 응답이 2초 안에 온다.

## Assumptions

- 글자 크기·줄 간격(본문 16.5px·1.85)은 이미 티스토리(16px·1.75)보다 넉넉해 유지한다.
- 강조색(#ff5a3c)·Pretendard 글꼴·미니룸 그림·알약 모양 버튼은 유지한다. 목록 레이아웃 변경으로 NFR-03의 "글 카드 1열(PC 2열)"은
  "한 줄 목록"으로 바뀐다.
- 대표 사진 크기 조정(서버 리사이즈)은 하지 않는다. 원본을 작은 칸에 맞춰 보여 주고 늦게 불러온다(lazy).
- 외부 공유 서비스(카카오톡 공유 등)는 쓰지 않는다(헌법 II: 새 CDN·외부 의존성 없음). 브라우저 공유 창과 클립보드만 쓴다.
- 네이버 블로그 화면은 작업 환경의 브라우저에서 열 수 없어, 알려진 화면 구성과 티스토리·velog 실측을 근거로 했다.
- 데이터베이스 표·칸은 바꾸지 않는다(헌법 IV).
