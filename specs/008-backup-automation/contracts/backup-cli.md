# Contract: 백업·복원 도구

관련: FR-001~FR-007 · NFR-08·14·16

## tools/backup.py

```
python3 tools/backup.py [--daily] [--keep N] [--dest 폴더] [--quiet] [--kind auto|manual]   (root는 --allow-root가 있어야 함)
```

| 상황 | 출력(한국어) | 종료 코드 |
| --- | --- | --- |
| 백업 성공 | `백업했어요: backups/2026-10-08_140512 (글 23개 · 회원 5명 · 사진·파일 41개, 12.3MB)` + 지운 옛 백업 수 | 0 |
| `--daily`인데 오늘 백업 있음 | `오늘 백업이 이미 있어요: …`(`--quiet`면 출력 없음) | 0 |
| 다른 백업·복원 진행 중 | `다른 백업이나 복원이 진행 중이에요. 잠시 뒤 다시 실행하세요.` | 1 |
| 백업 위치가 남도 쓸 수 있는 폴더·남의 폴더 | `백업 위치 … 는 다른 사람도 쓸 수 있는 폴더예요 …` (그 폴더 권한은 바꾸지 않음) | 1 |
| root로 실행 | `root로 실행하면 …` | 1 |
| 오래된 백업을 지우지 못함 | 새 백업은 성공(`백업했어요`) + `주의: 오래된 백업 … 을 지우지 못했어요` | 0 |
| DB 무결성 실패·쓰기 실패 | `백업하지 못했어요: <이유>` (임시 폴더 지움, 옛 백업은 그대로) | 1 |

- 순서: 잠금 → 임시 폴더(700) → blog.db·회원 DB 온라인 백업 + integrity_check → sso.key·oauth.config.php·설정 파일 복사(600) → uploads(링크 또는 복사) →
  manifest(600) → 이름 바꿈 → 정리.
- 회원 DB·키·설정·uploads가 없으면 `missing`에 적고 계속. blog.db가 없으면 실패("블로그를 한 번 켠 뒤 백업하세요").
- 업로드는 지금 파일·앞 백업 파일·앞 목록의 SHA-256이 모두 같을 때만 하드 링크(앞 백업의 파일이 손상됐으면 새로 복사).
- 안전 백업(`before-restore`)은 blog.db가 없어도 있는 것을 모두 남기고, DB가 망가져 온라인 백업이 안 되면 파일째(+ `-wal`·`-shm`·`-journal`)
  남긴 뒤 `raw_copies`에 적는다.

## tools/restore.py

```
python3 tools/restore.py                 # 목록과 사용법
python3 tools/restore.py <백업 폴더> [--yes] [--dest 폴더] [--with-config] [--ports 8000,8080] [--php-socket 경로]
```

| 상황 | 결과 | 종료 코드 |
| --- | --- | --- |
| 목록 | 날짜·종류·글 수·회원 수·크기 (읽을 수 없는 폴더는 건너뜀) | 0 |
| manifest 없음·주인이 내가 아님·알 수 없는 경로·DB·키·설정 확인값 다름 | `이 백업은 손상됐거나 바뀌었어요: …` 아무것도 안 바꿈 | 1 |
| 업로드만 확인값 다름 | 나머지는 되돌리고 `백업 속 … 파일이 손상돼 되돌리지 못했어요` (지금 파일이 맞으면 그대로) | 0 |
| 서버 켜짐(localhost IPv4·IPv6 포트, PHP-FPM 소켓) | `서버가 켜져 있어요(…). 블로그와 회원 서버를 끈 뒤 다시 실행하세요.` 아무것도 안 바꿈 | 1 |
| 다른 백업·복원 진행 중 | `되돌리지 못했어요: 다른 백업이나 복원이 진행 중이에요 …` | 1 |
| root로 실행 | `root로 실행하면 …` | 1 |
| `--yes` 없이 | 무엇을 되돌릴지 보여 주고 `되돌릴까요? (y/N)` | — |
| 중간 실패 | 안전 백업으로 돌려놓고 `되돌리지 못해 원래 상태로 돌려놓았어요: …` (그것도 실패하면 직접 실행할 명령 안내) | 1 |
| 성공 | `되돌렸어요. 되돌리기 전 상태는 …_before-restore 에 있어요. 블로그를 다시 켜세요.` | 0 |

- 순서: 확인값 검사 → 서버 확인 → 백업 위치(와 되돌리는 백업의 위치) 잠금 → 안전 백업(있는 것이 하나라도 있으면) → 1단계: 바꿀 파일을 모두 대상 폴더의
  숨은 임시 파일로 준비(처음부터 600·이미 있는 파일과 링크를 따라가지 않음) → 2단계: 두 DB의 `-wal`·`-shm`·`-journal`을 지우고 `os.replace`로 한꺼번에
  바꿔 넣기 → 백업에 없는 업로드 치움 → 실패하면 안전 백업 그대로(`mirror`)로 돌려놓기.
- 대상: 두 DB(백업에 없으면 지움, 짝을 맞춤)·sso.key·업로드는 백업 그대로. 설정 파일(deploy.config.json·oauth.config.php)은 이 컴퓨터에 있으면 그대로
  두고, 없을 때만 백업에서 가져옴(`--with-config`면 백업 그대로, 백업에 없으면 지움). 설정 파일 위치는 `MYBLOG_CONFIG`가 있으면 그 경로.

## 확인 목록 (tests/smoke_backup.py)

1. 백업 내용: 두 DB(WAL에만 있던 회원 포함)·키·설정·uploads, manifest 확인값, 무결성, 권한(700·600)
2. `--daily` 두 번 → 하나, `--keep` 정리 규칙(안전 백업·다른 폴더 보존)
3. 업로드 하드 링크(같은 inode), 새 파일만 복사
4. 서버 포트 열림(IPv4, IPv6가 되는 환경이면 ::1도) → 복원 거절·변경 0, 잠금이 걸려 있으면 거절
5. 변조된 백업·블로그 폴더 밖 경로 → 거절·변경 0, 업로드만 손상된 백업은 나머지를 되돌리고 다음 백업은 손상 파일을 잇지 않음
6. 복원 → 백업 그대로(지운 글 돌아옴, 새 업로드 치움), 안전 백업, `-wal`·`-shm` 없음, 설정 파일은 그대로(`--with-config`면 백업 그대로)
7. 선택 파일이 없는 환경에서 백업·복원
8. blog.db가 없거나 망가져도 안전 백업(파일째), 중간 실패 시 원래대로, 남도 쓰는 백업 위치·root 실행 거절
