# Research: 넓은 글쓰기 화면과 발행 설정 창

## D1. 무엇을 창으로 옮기나

- **Decision**: 글 종류·제목·본문은 편집 화면, 카테고리·공개·태그·대표 사진은 발행 설정 창.
- **Rationale**: 네이버 블로그(스마트에디터) 발행 창이 카테고리·공개·태그를 한곳에 모은다. 티스토리는 대표 이미지·공개를 발행 레이어에서 정한다.
  쓰는 동안 화면이 단순해지고, 발행 직전에 한 번 더 확인하게 된다.
- **Alternatives**: 태그를 편집 화면 아래(티스토리 방식)에 두기 → 화면에 칸이 다시 늘어남.

## D2. 대표 사진 저장 값

- **Decision**: `posts.cover` 하나: `''` 자동, `'none'` 사진 없이, 업로드 사진 주소. 읽을 때 고른 사진이 본문에 남아 있어야 쓴다.
- **Rationale**: 칸 하나만 더해 기존 글은 자동 그대로(헌법 IV). 본문에서 사진을 지우면 자동으로 돌아가 깨진 대표 사진이 남지 않는다.
- **Alternatives**: 대표 사진을 따로 올리기 → 업로드·정리 규칙이 늘어나 범위 밖.

## D3. 서버 검사

- **Decision**: `upload_images(content)` = 004의 `THUMB_RE`로 코드·주석 밖 업로드 사진을 순서대로(중복 제거) 모음. `cover`가 주소면 이 목록에 있어야 함.
  정규식은 004처럼 길이에 비례하는 식만 쓴다.

## D4. 나가기 경고

- **Decision**: `hashchange`에서 `leaveGuard()`가 false면 `revertingHash` 표시 후 이전 주소로 되돌리고 다시 그리지 않음. `beforeunload`는
  `event.preventDefault()`(브라우저 기본 문구). 변경 판단은 제목·본문·종류·창의 값이 열었을 때와 다른지.
- **Rationale**: 해시 라우터는 이동을 막을 수 없어 되돌리기로 처리. 확인 창 문구는 한국어.

## D5. 넓은 화면

- **Decision**: `body.editor-mode`에서 `.sidebar { display: none }`, `.layout` 1열. 도구 모음 `position: sticky; top: 107px`.
- **Rationale**: 티스토리처럼 편집에 집중. 지금은 편집 화면이 사이드바를 다시 그리지 않아 이전 화면의 것이 남는 문제도 함께 없어진다.

## D6. 독립 검토에서 찾은 문제와 해결 (구현 후 검토, 2026-10-08)

| 심각도 | 문제 | 해결 |
| --- | --- | --- |
| 중간 | 창에서 값을 바꾸면 600ms 뒤 임시 저장 예약이 걸리는데, 그 안에 발행하면 지운 임시 저장이 다시 생겨 다음 글쓰기에서 "작성 중이던 글"로 나옴(같은 글을 두 번 발행할 수 있음) | 발행 성공 때 예약 취소, 예약이 돌 때 `done`이면 쓰지 않음 |
| 중간 | 글을 불러오는 사이 다른 화면으로 가면 늦게 온 편집 화면이 그 화면을 덮거나 `editor-mode`·나가기 경고가 남음 | `renderEditor`도 `routeSeq` 확인 후 그림 |
| 낮음 | 로그아웃은 나가기 경고 없이 쓰던 글을 버림 | `logout()` 맨 앞에서 확인, 나가기로 하면 경고를 끄고 진행 |
| 낮음 | 발행 요청 중 창을 닫으면 실패 문구가 닫힌 창 안에만 남음 | 창이 닫혀 있으면 토스트로도 알림 |
| 낮음 | 대표 사진 선택지 키보드 포커스가 거의 안 보임(옅은 바탕 테두리), 창의 작은 안내 글자 대비 2.85:1 | 배경색 2px + 강조색 2px 링, 안내 글자 `--text-2` |
| 낮음 | 새 `fieldset.field` 규칙이 사이트 설정의 API 키 상자(점선 테두리)를 덮음 | 규칙을 `.publish-form` 안으로 한정 |

창에서 고른 값은 취소·Esc 뒤에도 남긴다(다시 열면 그대로). 티스토리 발행 창과 같고, 오타를 고치러 잠깐 닫았다 다시 여는 흐름을 위해서다. 그래서
창의 값을 바꾼 뒤 저장하지 않고 나가면 나가기 경고가 뜬다.
