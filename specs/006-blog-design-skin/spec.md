# Feature Specification: 블로그 꾸미기 — 대표 색·사이드바 구성·인기 글

**Feature Branch**: `006-blog-design-skin`

**Created**: 2026-10-08

**Status**: Implemented (2026-10-08)

**Input**: User description: "다음 작업 — 블로그 꾸미기: 블로그 주인이 대표 색(스킨)을 골라 블로그·글 화면에 적용, 사이드바/블로그 홈에 인기 글"

**관련 요구사항 ID**: BLOG-01·02·17(개정), NFR-01·04(개정) / 새 ID: BLOG-26(블로그 꾸미기: 대표 색·사이드바와 배너 항목), BLOG-27(인기 글)

**조사 근거**: 티스토리는 블로그 관리 → 꾸미기에서 스킨과 사이드바(모듈 켜고 끄기)를 정하고, 사이드바에 '인기 글' 모듈을 둘 수 있다. 네이버
블로그도 '꾸미기 설정'에서 스킨(색)·레이아웃·위젯 보이기를 고르고 인기글을 보여 준다. 지금 우리 블로그는 모든 블로그가 같은 주황(코랄) 강조색이고,
사이드바 항목을 고를 수 없으며, 많이 본 글은 블로그 관리 홈에서 주인만 본다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 내 블로그에 내 색을 입힌다 (Priority: P1)

블로그 주인은 블로그 관리 → 꾸미기에서 대표 색 8가지 중 하나를 미리 보고 저장한다. 그 뒤 내 블로그 화면과 내 글 화면은 방문자에게도 그 색(버튼·
선택된 메뉴·태그·링크 강조)으로 보인다. 라이트·다크 모드 모두 읽기 좋은 색으로 바뀐다.

**Why this priority**: 사용자가 고른 핵심 기능이다.

**Independent Test**: 꾸미기에서 '파랑'을 골라 저장 → 내 블로그와 내 글을 열어 강조색이 파랑인지, 블로그 홈(사이트)과 다른 사람 블로그는 원래 색인지 본다.

**Acceptance Scenarios**:

1. **Given** 블로그 주인, **When** 블로그 관리 → 꾸미기를 열면, **Then** 대표 색 8가지(코랄(기본)·파랑·초록·청록·보라·분홍·겨자·먹색)와 미리보기가 보이고,
   색을 고르면 미리보기만 바로 바뀐다.
2. **Given** '파랑'을 저장, **When** 누구든 그 블로그(#/@아이디)나 그 블로그의 글을 열면, **Then** 버튼·선택된 메뉴·태그·링크 강조가 파랑이다.
3. **Given** 그 상태에서 블로그 홈(사이트)·다른 사람 블로그·블로그 관리·글쓰기로 가면, **Then** 원래 색(코랄)으로 돌아온다.
4. **Given** 다크 모드, **Then** 같은 색의 밝은 버전이 쓰이고, 강조색 바탕 버튼의 글자는 어두운 색이라 읽힌다.

---

### User Story 2 - 인기 글을 보여 준다 (Priority: P1)

방문자는 개인 블로그 사이드바와 블로그 홈 사이드바에서 조회수가 많은 공개 글 5개를 순위와 함께 보고 바로 들어간다.

**Why this priority**: 사용자가 고른 핵심 기능이고, 새 방문자가 볼 글을 고르기 쉽다.

**Independent Test**: 조회수가 다른 공개 글 여러 개와 비공개 글이 있는 블로그를 열어 사이드바 '인기 글'이 조회수 순 5개(공개 글만)인지 본다.

**Acceptance Scenarios**:

1. **Given** 조회수 1 이상인 공개 글이 있는 블로그, **When** 그 블로그를 열면, **Then** 사이드바에 '인기 글'이 조회수 많은 순(같으면 최근 글 먼저)으로
   최대 5개, 순위 숫자·제목·조회수·대표 사진(있으면)과 함께 보인다.
2. **Given** 블로그 홈(사이트), **Then** 사이드바에 사이트 전체 공개 글의 '인기 글' 5개가 블로그 이름과 함께 보인다.
3. **Given** 비공개 글이 조회수가 가장 많아도, **Then** 인기 글에는 나오지 않는다(주인·관리자가 볼 때도).
4. **Given** 조회수 1 이상인 공개 글이 없으면, **Then** '인기 글' 칸이 보이지 않는다.

---

### User Story 3 - 사이드바와 배너에 보일 항목을 고른다 (Priority: P2)

블로그 주인은 꾸미기에서 미니룸(블로그 위)·글 종류·인기 글·태그·최근 댓글·방문자 수를 켜고 끈다. 끈 항목은 방문자에게 보이지 않는다.

**Why this priority**: 꾸미기의 기본 기능이지만 대표 색·인기 글보다는 덜 급하다.

**Independent Test**: 방문자 수·미니룸을 끄고 저장 → 로그아웃한 방문자로 그 블로그를 열어 두 항목이 없고, API 응답에도 방문자 수가 없는지 본다.

**Acceptance Scenarios**:

1. **Given** 꾸미기의 사이드바·배너 항목, **When** '방문자 수'를 끄고 저장하면, **Then** 그 블로그 사이드바에 방문자 칸이 없고, 블로그 API도 방문자 수를
   보내지 않는다.
2. **Given** '미니룸'을 끄면, **Then** 블로그 위 배너에 미니룸 그림이 없고 이름·소개·버튼만 남는다.
3. **Given** 프로필·카테고리, **Then** 항상 보인다(끌 수 없음).
4. **Given** 다시 켜면, **Then** 원래대로 보인다.

---

### Edge Cases

- 서버로 목록에 없는 색·이상한 값(숫자, 목록, 긴 문자열)을 보내면? → 400 "목록에 있는 색만 고를 수 있어요."
- 사이드바 항목에 모르는 이름이 섞여 오거나 목록이 아니면? → 400 "사이드바 항목을 다시 골라 주세요." 같은 이름이 두 번 오면 한 번으로.
- 예전 blog.db(색·항목 정보 없음)? → 코랄·모든 항목 보임과 같다(칸만 자동 추가).
- 블로그를 보다가 블로그 홈으로 가면? → 화면을 그리기 전에 원래 색으로 돌아온다. 같은 블로그 안에서 이동하면 색이 깜빡이지 않는다.
- 블로그 A를 불러오는 사이 블로그 B나 블로그 홈으로 이동하면? → 늦게 도착한 A는 그리지 않고 A의 색도 입히지 않는다.
- 인기 글의 대표 사진을 못 불러오면? → 사진만 빠지고 제목은 그대로다.
- 사이트 화면 모드(시스템·라이트·다크)를 바꾸면? → 다시 그리지 않아도 고른 색의 라이트/다크 버전으로 바로 바뀐다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 블로그 관리에 MUST '꾸미기' 탭을 두고, 대표 색 8가지와 미리보기, 사이드바·배너 항목 켜고 끄기, 저장 버튼(바뀐 것이 있을 때만)을
  보인다. (새 BLOG-26)
- **FR-002**: 대표 색은 MUST 그 블로그 화면(#/@아이디 아래 모든 목록)과 그 블로그 글 화면에만 적용되고, 블로그 홈·다른 블로그·블로그 관리·글쓰기·
  내 정보·사이트 설정은 기본색이다. (새 BLOG-26)
- **FR-003**: 각 색은 MUST 라이트·다크 두 버전이 있고, 라이트 강조색은 흰 바탕 대비 4.5:1 이상(기본 코랄은 지금 색 유지), 다크 강조색은 어두운 바탕
  대비 4.5:1 이상, 강조색 바탕 위 글자는 라이트 흰색·다크 어두운 색이다. (NFR-01·NFR-04 개정, 헌법 VI)
- **FR-004**: 서버는 MUST 목록에 있는 색 이름과 사이드바 항목 이름만 저장한다. (헌법 I)
- **FR-005**: 인기 글은 MUST 공개 글 중 조회수 1 이상을 조회수 많은 순(같으면 최근 글 먼저) 최대 5개로, 개인 블로그는 그 블로그 글, 블로그 홈은
  사이트 전체 글에서 서버가 고른다. 각 항목은 제목·조회수·대표 사진(BLOG-20 규칙)·(블로그 홈은) 블로그 이름. (새 BLOG-27, 헌법 I)
- **FR-006**: 블로그 주인이 끈 사이드바 항목(인기 글·태그·최근 댓글·방문자 수)은 MUST 블로그 API가 그 자료를 보내지 않고, 화면은 그 칸을 그리지
  않는다. 글 종류는 위쪽 종류 탭이 쓰므로 자료는 보내고 사이드바 칸만 숨긴다. 미니룸을 끄면 배너에 그림을 그리지 않는다. (새 BLOG-26, BLOG-02·17 개정)
- **FR-007**: 색·항목 정보는 MUST 기존 DB에 칸을 더하는 방식으로만 저장한다(기존 블로그는 기본값). (헌법 IV)
- **FR-008**: 꾸미기 화면은 MUST 키보드로 조작되고(색은 라디오 묶음, 화살표로 이동), 라이트·다크·375px에서 읽힌다. (NFR-03, NFR-10)
- **FR-009**: 구현 후 MUST requirements.md 두 사본과 원본 문서에 BLOG-26~27을 더하고 BLOG-01·02·17, NFR-01·04를 고친다. (헌법 V)

### Key Entities

- **회원 블로그(users)**: `skin`(색 이름, 기본 `coral`), `hidden_widgets`(끈 항목 이름 JSON 목록, 기본 `[]`) 칸 추가.
- **인기 글**: 저장하지 않고 응답을 만들 때 계산 — `{id, title, type, views, thumbnail}`(+ 블로그 홈은 `blog_title`, `author_username`).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 색을 저장한 블로그의 화면·글 화면에서 강조색이 100% 그 색이고, 블로그 홈·다른 블로그·관리·글쓰기에서는 100% 기본색이다.
- **SC-002**: 8가지 색 모두 라이트(흰·옅은·회색 바탕)·다크에서 강조색 글자 대비 4.5:1 이상(기본 코랄 라이트 제외), 강조색 버튼 글자 대비 4.5:1
  이상(기본 코랄 라이트 제외).
- **SC-003**: 인기 글은 공개 글만, 조회수 순 최대 5개이고 비공개 글은 0개 나온다.
- **SC-004**: 목록에 없는 색·항목 값은 100% 거절된다. 끈 항목의 자료는 블로그 API 응답에 0건이다.
- **SC-005**: 기존 스모크 테스트(001~005)가 모두 통과하고, 375px에서 가로 넘침 0건.

## Assumptions

- 색은 정해진 8가지에서만 고른다(아무 색이나 고르는 색상환은 대비를 보장하기 어려워 이번 범위 밖).
- 블로그 홈(사이트 전체)의 색은 바꾸지 않는다(사이트 설정의 색 고르기는 범위 밖).
- 인기 글은 전체 기간 조회수로 정한다(날짜별 조회 기록이 없어 '최근 7일 인기'는 범위 밖).
- 항목 순서 바꾸기·글 목록 모양(앨범형) 고르기는 이번 범위 밖.
