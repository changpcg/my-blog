**관련 요구사항 ID**: BLOG-05(개정), BLOG-07, BLOG-20(개정), SEC-12 / 새 ID: BLOG-24(발행 설정 창·대표 사진 고르기), BLOG-25(넓은 편집 화면·글자 수·나가기 경고)

**조사 근거**: 티스토리 글쓰기는 블로그 사이드바 없이 화면 전체를 편집에 쓰고, 아래쪽 '완료'를 누르면 공개 설정·카테고리·대표 이미지 등을
정하는 발행 레이어가 열린다. 네이버 블로그(스마트에디터)도 '발행'을 누르면 카테고리·공개 설정·태그를 한 창에서 정한다. 지금 우리 편집기는
사이드바가 그대로 남아(이전 화면의 사이드바가 바뀌지 않고 남음) 편집 칸이 좁고, 카테고리·태그·공개가 제목 아래에 늘어서 있으며, 목록 대표 사진은
본문 첫 사진으로만 정해진다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 넓은 화면에서 글에만 집중한다 (Priority: P1)

글쓴이는 글쓰기·수정 화면에서 사이드바 없이 넓어진 편집 칸을 쓴다. 길게 써 내려가도 도구 모음은 화면 위쪽에 붙어 따라오고, 아래쪽에 지금까지 쓴
글자 수가 보인다.

**Why this priority**: 매번 쓰는 화면이라 효과가 가장 크고, 지금은 이전 화면의 사이드바가 남는 문제도 있다.

**Independent Test**: 글쓰기를 열어 사이드바가 없는지, 편집 칸이 화면 폭(최대 1100px)을 쓰는지, 내려도 도구 모음이 보이는지, 글자 수가 바뀌는지 본다.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원, **When** 글쓰기(또는 수정)를 열면, **Then** 사이드바(위젯 포함)가 사라지고 편집 화면이 본문 폭 전체를 쓴다.
   다른 화면으로 가면 사이드바가 돌아온다.
2. **Given** 긴 글을 쓰며 아래로 내려가면, **Then** 도구 모음이 위쪽 고정 바 바로 아래에 붙어 있다.
3. **Given** 글을 쓰는 동안, **Then** 아래쪽에 "글자 N · 공백 제외 M"이 바로바로 바뀐다.
4. **Given** 휴대폰(375px), **Then** 편집 화면이 옆으로 넘치지 않는다.

---

### User Story 2 - 발행 설정 창에서 마지막으로 정한다 (Priority: P1)

글쓴이는 '발행'(수정이면 '저장')을 누르면 뜨는 발행 설정 창에서 카테고리·공개 여부·태그·대표 사진을 정하고, 목록에 어떻게 보일지 미리 본 뒤
발행한다.

**Why this priority**: 사용자가 고른 핵심 기능이다.

**Independent Test**: 사진 두 장이 있는 글을 쓰고 '발행' → 창에서 두 번째 사진을 대표로 골라 발행 → 블로그 홈 목록에 두 번째 사진이 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 제목을 쓰고 '발행'을 누르면, **Then** 발행 설정 창이 열리고 카테고리·공개 설정(공개/비공개)·태그·대표 사진·목록 미리보기가 보인다.
   제목이 비어 있으면 창 대신 "제목을 입력하세요"가 나오고 제목 칸으로 간다.
2. **Given** 본문에 이 블로그에 올린 사진이 있으면, **Then** 대표 사진 칸에 "자동(본문 첫 사진)", "사진 없이", 그리고 그 사진들이 보이고 하나를 고를 수 있다.
   외부 주소 사진은 고를 수 없다.
3. **Given** 대표 사진을 고르면, **Then** 미리보기의 사진이 바로 바뀌고, 발행 후 목록·관련 글 카드에 그 사진이 쓰인다. "사진 없이"면 목록에 사진 칸이 없다.
4. **Given** 카테고리가 필요한 종류(일상 제외, 카테고리가 있는 블로그)인데 고르지 않으면, **Then** 창 안에서 "카테고리를 선택하세요"가 보이고 발행되지 않는다.
5. **Given** 창의 '취소'·Esc, **Then** 창만 닫히고 쓰던 글은 그대로다.
6. **Given** 수정 화면, **Then** 창이 지금 값(카테고리·공개·태그·대표 사진)으로 채워져 열린다.

---

### User Story 3 - 쓰던 글을 실수로 잃지 않는다 (Priority: P2)

글쓴이가 저장하지 않은 채 다른 메뉴를 누르거나 창을 닫으려 하면 확인을 받는다.

**Why this priority**: 수정 중인 글은 임시 저장이 없어 잃기 쉽다.

**Independent Test**: 글을 고치다가 상단 메뉴를 눌러 확인 창이 뜨는지, 취소하면 그대로 남는지, 발행 뒤에는 묻지 않는지 본다.

**Acceptance Scenarios**:

1. **Given** 내용을 바꾼 뒤, **When** 다른 화면으로 가려 하면, **Then** "작성 중인 내용이 있어요. 이 화면을 나갈까요?"를 묻고, 취소하면 편집 화면과 주소가 그대로다.
2. **Given** 브라우저 탭을 닫거나 새로 고치려 하면, **Then** 브라우저 기본 경고가 뜬다.
3. **Given** 아무것도 바꾸지 않았거나 발행·저장을 마쳤으면, **Then** 묻지 않는다.

---

### Edge Cases

- 대표 사진으로 고른 사진을 나중에 본문에서 지우면? → 목록은 다시 자동(본문 첫 사진)으로 돌아간다.
- 서버로 본문에 없는 사진·외부 주소·이상한 값을 대표 사진으로 보내면? → 400 "대표 사진은 본문에 있는 사진 중에서 골라 주세요."
- 본문에 사진이 하나도 없으면? → 대표 사진 칸에 "자동", "사진 없이"만 있고 자동이면 목록에 사진 칸이 없다.
- 예전 글(대표 사진 정보 없음)? → 자동과 같다.
- 임시 저장(새 글)에는 공개·카테고리·태그·대표 사진 선택도 함께 남는다.
- 발행 중 오류(카테고리 없음 등)? → 창 안에 한국어 오류가 보이고 창은 열린 채로 둔다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 글쓰기·수정 화면은 MUST 사이드바를 숨기고 본문 폭 전체를 쓰며, 다른 화면으로 가면 사이드바를 다시 보인다. (새 BLOG-25)
- **FR-002**: 편집 도구 모음은 MUST 내려도 위쪽 고정 바 아래에 붙어 있고, 편집 화면 아래에 글자 수(전체·공백 제외)를 보인다. (새 BLOG-25)
- **FR-003**: '발행'/'저장'은 MUST 발행 설정 창을 연다. 창에는 카테고리·공개 설정·태그·대표 사진·목록 미리보기가 있고, 창의 '발행'/'저장'으로만 서버에
  보낸다. 제목이 비면 창을 열지 않는다. (새 BLOG-24, BLOG-05 개정)
- **FR-004**: 대표 사진 선택지는 MUST 자동·사진 없이·본문에 있는 이 블로그 업로드 사진들이다. (새 BLOG-24)
- **FR-005**: 서버는 MUST 대표 사진 값을 `''`(자동)·`'none'`(사진 없이)·본문에 있는 업로드 사진 주소만 받고, 목록·관련 글 대표 사진은 고른 사진이
  본문에 남아 있을 때만 그 사진, `'none'`이면 없음, 그 밖에는 자동 규칙(BLOG-20)으로 정한다. (새 BLOG-24, BLOG-20 개정, 헌법 I)
- **FR-006**: 대표 사진 정보는 MUST 글마다 저장하되 기존 DB에 칸을 더하는 방식으로만 바꾼다(기존 글은 자동). (헌법 IV)
- **FR-007**: 편집 화면은 MUST 저장하지 않은 변경이 있을 때 화면 이동은 확인 창으로, 탭 닫기·새로 고침은 브라우저 경고로 막고, 발행·저장 뒤에는 묻지
  않는다. (새 BLOG-25)
- **FR-008**: 발행 설정 창은 MUST 키보드로 조작되고(Esc로 닫기, 포커스가 창 안에), 라이트·다크·375px에서 읽힌다. (NFR-04, NFR-10, NFR-03)
- **FR-009**: 구현 후 MUST requirements.md 두 사본과 원본 문서에 BLOG-24~25를 더하고 BLOG-05·BLOG-20을 고친다. (헌법 V)

### Key Entities

- **글(posts)**: `cover` 칸 추가 — `''`(자동), `'none'`(사진 없이), `/uploads/<32자리>.png|jpg|gif|webp`(고른 사진).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 글쓰기·수정 화면에서 사이드바 0개, 1280px에서 편집 칸 폭이 1000px 이상, 375px에서 가로 넘침 0건.
- **SC-002**: 사진 두 장 글에서 두 번째 사진을 고르고 발행하면 목록·관련 글 대표 사진이 100% 그 사진이고, "사진 없이"면 사진 칸이 0개다.
- **SC-003**: 본문에 없는 사진·외부 주소·임의 문자열을 대표 사진으로 보내면 100% 거절된다.
- **SC-004**: 저장하지 않은 변경이 있을 때 화면 이동 시도 100%에서 확인을 받고, 발행 뒤 이동에서는 0번 묻는다.
- **SC-005**: 기존 스모크 테스트(001~004)가 모두 통과한다.

## Assumptions

- 공개 설정은 지금처럼 공개/비공개 두 가지(보호글·예약 발행은 이번 범위 밖).
- 태그는 발행 설정 창에서 쉼표로 적는다(서버 규칙 BLOG-05 그대로: 20개, 쉼표·#).
- 글 종류 고르기와 제목·본문은 편집 화면에 그대로 두고, 카테고리·공개·태그를 창으로 옮긴다.
- 사진 업로드 방식(붙여넣기·드래그·버튼)과 임시 저장 방식은 그대로다.
