# Research: 블로그 꾸미기 — 대표 색·사이드바 구성·인기 글

**Date**: 2026-10-08 | **Spec**: [spec.md](./spec.md)

## 조사

| 서비스 | 가져온 점 |
| --- | --- |
| 티스토리 | 블로그 관리 → 꾸미기(스킨 변경·스킨 편집·사이드바 모듈 켜고 끄기), 사이드바 '인기 글' 모듈(제목·사진), 스킨 색은 블로그 화면에만 |
| 네이버 블로그 | 꾸미기 설정(스킨 색·레이아웃·위젯 보이기), 인기글 목록(순위·사진), 블로그마다 색이 달라도 네이버 공통 메뉴는 그대로 |
| 우리 블로그(지금) | 강조색 하나(라이트 #ff5a3c·다크 #ff7a5f)를 CSS 변수 `--accent`·`--accent-soft`로 78곳에서 씀, 강조색 바탕 글자는 `#fff` 고정(다크에서 2.6:1) |

## 결정

### D1. 색 8가지와 값

| 이름 | 키 | 라이트 강조 / 옅은 바탕 | 흰 바탕 대비 | 다크 강조 / 옅은 바탕 | #161616 대비 |
| --- | --- | --- | --- | --- | --- |
| 코랄(기본) | coral | #ff5a3c / #fff1ed | 3.10 | #ff7a5f / #2e1d18 | 7.07 |
| 파랑 | blue | #2563eb / #eef3fe | 5.17 | #6b9cff / #172238 | 6.74 |
| 초록 | green | #15803d / #ecf7f0 | 5.02 | #4cc77f / #14271c | 8.43 |
| 청록 | teal | #0f766e / #e9f6f4 | 5.47 | #2fc4b2 / #122826 | 8.32 |
| 보라 | purple | #7c3aed / #f4effe | 5.70 | #a98bff / #251c38 | 6.74 |
| 분홍 | pink | #be185d / #fdeef5 | 6.04 | #f472b6 / #331a28 | 6.83 |
| 겨자 | mustard | #a16207 / #fbf5e6 | 4.92 | #facc15 / #2d2611 | 11.82 |
| 먹색 | ink | #3f3f46 / #f2f2f3 | 10.44 | #d4d4d8 / #27272a | 12.24 |

- **Decision**: 위 8가지. 새 색은 라이트에서 흰 바탕·옅은 바탕(`--accent-soft`)·회색 바탕(`--bg-soft`) 모두 4.5:1 이상(강조색 글자·흰 글자 버튼
  모두 통과), 다크에서 #161616 대비 6.7:1 이상.
  기본 코랄 라이트(3.10:1)는 지금 블로그의 얼굴이라 그대로 두고 예외로 적는다(1.4.11 UI 요소 3:1은 통과).
- **Alternatives**: 색상환(아무 색) → 대비를 보장할 수 없음. 주황 계열(#c2410c) → 코랄과 구분이 안 돼 겨자로 바꿈. 남색 → 파랑과 겹침.

### D2. 적용 방법: `<html data-skin>` + CSS 변수

- **Decision**: `[data-skin="blue"] { --accent; --accent-soft }`(라이트), `:root[data-theme="dark"][data-skin="blue"], :root[data-theme="dark"]
  [data-skin="blue"]`와 `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"])[data-skin="blue"], … }`(다크). 같은 규칙이
  `<html>`(블로그 전체)과 꾸미기 미리보기 카드(그 안만) 모두에 걸린다. 코랄은 속성을 지움(기본 변수 그대로).
- **Specificity**: 라이트 색 규칙(0,1,0)은 기본 `:root`(0,1,0)보다 뒤에 있어 이기고, 다크 기본 `:root[data-theme="dark"]`(0,2,0)에는 지며,
  다크 색 규칙(0,3,0)이 다시 이긴다 → 화면 모드를 바꿔도 다시 그릴 필요 없음.
- **새 변수 `--on-accent`**: 강조색 바탕 위 글자(`.btn.primary`, FAQ Q, 용어 색인 hover, 대표 사진 선택 표시 등). 라이트 #fff, 다크 #161616.
  다크 코랄 버튼 글자 대비 2.56 → 7.07.
- **Alternatives**: `style.setProperty`로 색 직접 넣기 → 화면 모드를 바꿀 때마다 다시 계산해야 함. 색마다 CSS 파일 → 요청 늘고 깜빡임.

### D3. 언제 색을 바꾸나

- **Decision**: `render()` 시작 때 블로그 화면(`@…`)·글 화면(`post/…`)이 아니면 바로 `setSkin('')`. 블로그·글 화면이면 지금 색을 두고(같은 블로그
  안 이동에 깜빡임 없음) 응답을 받은 뒤 `setSkin(b.skin)`. `renderBlog()`도 `renderPost()`처럼 `routeSeq`를 확인해 늦게 온 블로그는 그리지도,
  색을 입히지도 않는다.
- **Rationale**: 블로그 홈으로 돌아갈 때 이전 블로그 색이 남아 보이는 시간을 없앰. 다른 블로그로 바로 갈 때는 응답 전까지 이전 색이 잠깐 남지만 화면
  내용도 이전 것이라 어긋나지 않음.

### D4. 인기 글 기준

- **Decision**: 공개 글(`is_public = 1`) 중 `views >= 1`, `ORDER BY views DESC, created_at DESC, id DESC LIMIT 5`. 블로그는 `author_id = 블로그`,
  사이트는 전체(회원이 있는 글만). 보는 사람과 관계없이 같은 목록(주인·관리자도 비공개 글 빠짐).
- **Rationale**: 공개 위젯이라 보는 사람마다 목록이 달라지면 헷갈림. 조회수 0만 있는 블로그에서 '인기'가 최신 글이 되는 것을 막음.
- **Alternatives**: 최근 7일 인기 → 날짜별 조회 기록이 없음(새 표 필요, 범위 밖). 공감 수 순 → 공감이 적은 초기에는 거의 0.

### D5. 끈 항목은 서버가 자료를 빼고 보낸다

- **Decision**: `popular`·`tags`·`recent_comments`는 `[]`, `stats`는 `null`. `type_counts`는 위쪽 글 종류 탭이 쓰므로 그대로 보내고 사이드바
  칸만 숨김. 미니룸 값(room_bg·room_char)은 그림 이름뿐이라 그대로.
- **Rationale**: 방문자 수를 숨기고 싶은 주인의 뜻을 API에서도 지킴(헌법 I). 블로그 관리의 통계는 따로(`manage/stats`) 있어 주인은 영향 없음.

### D6. 저장은 `PUT /api/me`

- **Decision**: 미니룸처럼 본인 정보 수정 API에 `skin`(문자열, 허용 목록)·`hidden_widgets`(문자열 목록, 허용 이름만, 중복 제거, 최대 6개)를 더함.
  오류: "목록에 있는 색만 고를 수 있어요." / "사이드바 항목을 다시 골라 주세요."
- **Alternatives**: 새 `manage/design` API → 같은 권한 검사를 또 만들 필요 없음.

### D7. 꾸미기 화면

- **Decision**: 색은 `label.skin-opt[data-skin] > input[type=radio] + .skin-face`(진짜 라디오라 Tab 한 번 + 화살표로 이동, 화면 읽기에 이름·선택
  상태가 그대로), 미리보기는 `div.skin-preview[data-skin]` 안에 작은 배너·종류 칩·글쓰기 버튼·태그·링크. 항목은 기존 `.switch` 체크박스.
  저장 버튼은 바뀐 것이 있을 때만 '저장', 아니면 '저장됨'(미니룸과 같음). 저장 뒤 '내 블로그에서 보기 →'.

### D8. 독립 검토에서 찾은 문제와 해결 (구현 후 검토, 2026-10-08)

| 심각도 | 문제 | 해결 |
| --- | --- | --- |
| 중간 | 분홍(#db2777)이 자기 옅은 바탕(#fdeef5) 위에서 4.10:1 — 선택된 칩·이웃 버튼·회원 표시 글자가 기준 미달(흰 바탕만 쟀음) | #be185d(흰 6.04·옅은 바탕 5.38·회색 바탕 5.63), D1 표를 세 바탕 기준으로 |
| 중간 | 블로그 홈·이웃 새 글·관리·사이트 설정은 `routeSeq` 확인이 없어, 느린 응답이 다른 블로그 화면을 덮으면 그 블로그 색 위에 엉뚱한 내용이 보임 | 모든 비동기 화면이 응답 뒤 `routeSeq`를 확인(맛집·로그인 사이드바 포함) |
| 낮음 | 미니룸을 끄면 배너 안쪽 줄이 배너 폭을 다 쓰지 않아 이웃 버튼이 가운데로 오고 여백이 두 번 | 미니룸 없는 배너의 줄은 `flex: 1`, 안쪽 여백 0 |
| 낮음 | 꾸미기 항목 체크박스에 포커스 표시가 없음(`.field input { outline: none }`), 두 카드 사이 간격 0 | `:focus-visible` 2px 테두리, `#designForm` 간격 20px |
| 낮음 | 먹색에서는 사이드바의 지금 카테고리가 색만 달라 구분이 거의 안 됨(1.8:1) | 지금 카테고리는 굵게(색 말고 다른 표시) |

블로그 색은 `<html>`에 걸려 그 블로그 화면에서는 위쪽 공통 바(글쓰기 버튼 등)도 같은 색이 된다. 네이버는 공통 메뉴를 그대로 두지만 우리 위쪽 바는
블로그 화면의 일부처럼 보여 한 화면에 두 색이 섞이지 않게 하려고 이렇게 둔다(티스토리 스킨도 머리 부분까지 바뀜).
