# Research: 담백한 디자인과 읽기 좋은 글 화면

**Date**: 2026-10-08 | **Spec**: [spec.md](./spec.md)

## 조사한 화면

| 서비스 | 확인 방법 | 가져온 점 |
| --- | --- | --- |
| 티스토리(공지 블로그, 스킨 기본형) | 브라우저로 직접 열어 확인 | 얇은 구분선·여백 위주, 글 위 카테고리→제목→작성자·날짜, 본문 16px·줄 간격 1.75, 글 아래 좋아요·공유하기·구독하기 한 줄, 작성자 상자, 같은 카테고리 글 4개 사진 카드, 이전·다음 글 |
| velog | 브라우저로 직접 열어 확인 | 넓은 화면의 목차(소제목으로 이동), 제목 아래 태그, 이전·다음 글 카드, 코드 블록 강조 |
| 네이버 블로그 | 작업 환경 브라우저에서 접속 차단 → 알려진 화면 구성으로 대신 | 목록 오른쪽 정사각형 대표 사진, 공감·댓글 수, 같은 카테고리 다른 글, 이웃 추가, 휴대폰에서 정보 줄이 사진 아래까지 |
| 우리 블로그(변경 전) | 화면 캡처(라이트·다크 × 1280·375) | PC 3px 테두리·6px 그림자 카드 2열, 사진이 카드 위에 16:9로 크게, 375px 글 보기에서 페이지 폭 479px(넘침) |

## 결정

### D1. 디자인 규칙: 1px 선 + 12px 둥글기 + 그림자 없음

- **Decision**: `.card` 한 규칙으로 통일(`border: 1px solid var(--line)`, `border-radius: var(--radius)`=12px). 마우스를 올리면
  `--line-strong` 선과 `--shadow-soft`(0 2px 12px, 5%)만. 떠 있는 내 메뉴만 `--shadow-pop`. 다크 모드 값 따로.
- **Rationale**: 사용자가 고른 "티스토리처럼 담백하게". 변수만 바꾸면 블로그 관리·사이트 설정·미니룸 등 기존 카드도 함께 바뀐다.
- **Alternatives**: 그림자만 줄이고 3px 테두리 유지 → 여전히 무거움. 테두리 없이 배경색만 → 다크 모드에서 구분이 약함.

### D2. 375px 넘침 원인과 해결

- **Decision**: 900px 이하 `.layout { grid-template-columns: minmax(0, 1fr) }`.
- **Rationale**: `1fr`은 `minmax(auto, 1fr)`이라 열의 최소 폭이 내용(긴 `pre`의 한 줄) 폭이 됨 → 페이지가 479px로 넓어짐. PC는 이미
  `minmax(0, 1fr)`라 문제가 없었다. 표는 `body`의 `overflow-wrap: anywhere` 때문에 칸이 한 글자 폭까지 줄어 글자가 세로로 끊겼으므로
  칸만 `break-word`로 바꿔 표가 자기 폭을 갖고 표 안에서 옆으로 밀리게 한다.
- **Alternatives**: `pre { white-space: pre-wrap }` → 코드 줄이 꺾여 읽기 어려움. `body { overflow-x: hidden }` → 넘침을 숨길 뿐
  가로 흔들림·잘림이 남음.

### D3. 대표 사진은 서버가 고른 "올린 사진"만

- **Decision**: `first_upload_image(text)`: 코드 블록(``` ··· ```, ~~~, 인라인 `)을 지운 뒤 마크다운 `![](주소)`(앞뒤 띄어쓰기·꺾쇠·제목 허용)
  또는 HTML `<img src>`에서 `/uploads/<32자리 16진수>.(png|jpg|gif|webp)`만 첫 번째로 고른다.
- **Rationale**: 기존 정규식은 `( /uploads/x.png )`처럼 띄어쓰기가 있거나 HTML 사진이면 놓쳤고, 외부 주소 사진도 그대로 목록에 실어
  방문자 목록 화면에서 외부 추적 사진이 불릴 수 있었다(SEC 관점). 업로드 이름 형식은 서버가 만든 것만 통과.
- **Alternatives**: 글 저장 때 대표 사진 칸을 DB에 저장 → 스키마 변경(헌법 IV는 허용하지만 필요 없음, 기존 글에도 바로 적용되는 계산식이 단순).
  사용자가 대표 사진을 고르기 → 이번 범위 밖.

### D4. 관련 글 4개, 사진 카드

- **Decision**: 같은 블로그·종류·카테고리, `visible()` 조건, 최신순(`created_at DESC, id DESC`) 4개. 응답에 `type`·`is_public`·`thumbnail`
  추가, 본문은 응답에서 뺀다. 사진 없으면 종류 아이콘 자리.
- **Rationale**: 티스토리처럼 한 줄 4칸(PC)·2칸(900px 이하)이 정돈된다. 비공개 여부는 서버가 정한다(원칙 I).

### D5. 목차 이동은 해시를 바꾸지 않는다

- **Decision**: 목차 링크는 `href="#/post/ID"`(새 탭으로 열면 같은 글) + `data-toc` 순번. 클릭은 `preventDefault` 후 `jumpTo()`:
  소제목에 `tabindex=-1`·포커스(preventScroll) → `scrollIntoView`(동작 줄이기면 즉시). 위치 보정은 CSS `scroll-margin-top: 124px`.
- **Rationale**: 해시 라우터라 `#소제목`을 쓰면 라우터가 "페이지 없음"으로 감. 같은 이름 소제목도 순번으로 구분. 용어 사전 색인 이동도
  같은 `jumpTo()`로 바꿔 '동작 줄이기'를 존중하게 함.

### D6. 진행 막대와 맨 위로

- **Decision**: 본문(`#postContent`) 기준: 진행 = (고정 바 높이 110 − 본문 top) ÷ (본문 높이 − (화면 높이 − 110)), 0~1. 본문이 화면보다 짧으면
  본문 끝이 보일 때 1. `scroll`·`resize`를 rAF로 묶고, 라우터가 화면을 바꿀 때 `stopReadingTools()`로 리스너 제거·숨김.
- **Rationale**: 댓글까지 포함하면 "다 읽음"이 늦게 와서 본문만 센다. 장식이라 `aria-hidden`.

### D7. 공유하기

- **Decision**: `navigator.share`(있고 `canShare` 통과) → 사용자가 닫으면(AbortError) 끝. 없으면 `copyText(location.href)`:
  보안 연결이면 Clipboard API, 아니면 숨은 textarea + `execCommand('copy')`. 둘 다 실패하면 읽기 전용 주소 칸을 보여 주고 선택해 둠.
- **Rationale**: 카카오톡 공유 등 외부 SDK는 헌법 II 위반(새 CDN). 다른 기기에서 `http://IP:8000`으로 열면 Clipboard API가 막히므로 예전
  방식까지 시도.

### D8. 사진 크게 보기는 `<dialog>`

- **Decision**: `renderMd()`에서 링크가 없는 사진을 `<button class="img-zoom" aria-label="사진 크게 보기: 대체 글">`로 감쌈. 클릭 위임으로
  `dialog.showModal()` → 뒤쪽 화면은 자동으로 비활성(포커스 가둠), Esc는 기본 동작, 바깥(사진 외) 클릭·닫기 버튼으로 닫음, `close`에서
  원래 버튼으로 포커스. 열린 동안 `html.lb-open { overflow: hidden }`.
- **Rationale**: 모달 대화상자의 포커스 가둠·Esc·접근성을 브라우저가 처리해 코드가 짧다. 버튼으로 감싸 키보드로 열 수 있다.
- **Alternatives**: `img`에 `tabindex`+`role=button` → 대체 글 의미가 흐려짐. 직접 만든 오버레이 → 포커스 가둠을 손으로 구현해야 함.

### D9. 코드 머리와 복사

- **Decision**: 강조(highlight.js) 전에 글쓴이가 적은 `language-xxx`만 읽어 이름표(`CODE_LANG` 표, 없으면 "코드")를 만든다. 자동 감지
  결과는 쓰지 않는다(짧은 코드에서 틀리기 쉬움). 복사 성공은 버튼 글자 "복사했어요"(1.6초) + 화면 읽기용 알림(`#srStatus`), 실패는 토스트.

### D10. 목록은 grid 두 영역

- **Decision**: `.post-row.has-thumb`는 `"text thumb" / "meta thumb"`(PC), 휴대폰은 `"text thumb" / "meta meta"`로 날짜·댓글·조회 줄이 사진
  아래까지 쓰게 함. 사진이 깨지면 `error` 캡처 리스너가 사진과 `has-thumb`를 지워 빈 칸이 남지 않음.
- **Rationale**: 휴대폰에서 정보 줄이 좁은 글자 칸에 갇혀 두 줄로 꺾이던 문제(1차 캡처에서 확인)를 없앰.

### D11. 독립 검토에서 찾은 문제와 해결 (구현 후 검토, 2026-10-08)

| 심각도 | 문제 | 해결 |
| --- | --- | --- |
| 높음 | 대표 사진·요약 정규식(`<img\b[^>]*?`, `</?[a-zA-Z][^>]*>`, 기존 `!\[[^\]]*\]`)이 같은 기호를 되풀이한 본문에서 길이의 제곱으로 느려짐. 10만 자 본문 하나로 목록 16초, 그동안 다른 요청도 대기(파이썬 정규식이 GIL을 쥠) | 모든 식을 다음 구분 문자에서 멈추게(`[^<>]`, `[^\[\]\n]`, `[^()]`), 본문 20만 자 상한(`POST_MAX_CHARS`). 1MB 악성 본문도 0.2초 안 |
| 중간 | 본문 HTML이 `class="code-block"`·숨긴 `pre`로 가짜 코드 상자를 만들어 복사 버튼이 숨은 명령을 복사하게 할 수 있음. `data-nb` 버튼도 이웃 버튼으로 연결됨 | 글쓴이 class 제거(코드 언어 표시만), `ALLOW_DATA_ATTR: false`, 코드 칸 `style`·`hidden` 제거 |
| 중간 | 글을 불러오는 사이 다른 화면으로 가면 진행 막대·맨 위로가 그 화면에 남음 | `routeSeq`로 늦게 온 글은 그리지 않음 |
| 낮음 | 글 속 `id="shareUrl"`·`id="srStatus"`가 화면 요소와 겹침 | `SANITIZE_NAMED_PROPS: true`(글 속 id·name에 `user-content-`) |
| 낮음 | ```` ```constructor ```` 언어 이름이 함수 글자로 보임 | 자기 항목만 찾기(`hasOwnProperty`), 모르는 이름은 적힌 대로 |
| 낮음 | 목차 소제목·코드 언어 이름 대비 2.66:1, 복사 완료 3.58:1 | `--text-2`, #157347 |
| 낮음 | HTML 주석·두 겹 인라인 코드 속 사진을 대표 사진으로 고름, 문장 중간 ```가 뒤 내용을 지움, 인라인 코드 속 `<…>`가 요약에서 사라짐 | 줄 맨 앞 코드 울타리만, 주석·두 겹 코드 제외, 인라인 코드는 태그 지우기에서 보호 |
| 낮음 | 목차 Ctrl·Cmd 클릭(새 탭)이 막힘, 휴대폰 맨 위로 40px, 회원 화면 `--line`·입력 포커스 두께 | 보조 키 클릭은 브라우저에 맡김, 44px, #ebebea·포커스 2px |

들여쓰기(공백 4칸) 코드 블록 속 사진은 목록 안 줄 이어쓰기와 구분하기 어려워 대표 사진 판단에서 따로 빼지 않는다(편집기의 코드 블록 버튼은 ``` 울타리를 씀).
