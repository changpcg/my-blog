# Contract: 가입 보호 (회원 서버)

관련: US4, FR-012·013, 새 SEC-14 · 모델: [data-model.md §3·4](../data-model.md)

## 폼에 더하는 칸 (`register.php`, `social_signup.php`)

| 이름 | 종류 | 값·속성 |
| --- | --- | --- |
| `form_token` | hidden | 서버가 화면을 그릴 때 발급(32자 16진수) |
| `website` | text, 화면 밖으로 숨김 | 빈 값이어야 함. 감싸는 요소에 `aria-hidden="true"`, 입력에 `tabindex="-1"`·`autocomplete="off"`, 라벨 "이 칸은 비워 두세요" |

숨김은 `display:none`이 아니라 화면 밖 배치(CSS 클래스)로 한다(일부 봇은 display:none 칸을 건너뜀).

## 처리 순서 (POST, `action=signup`)

1. CSRF 확인(기존).
2. 가입 허용 확인 `signup_open()`(기존).
3. 입력 검사·아이디 중복 확인 통과 여부(기존). 오류면 보낸 토큰이 유효한 한 같은 토큰으로 폼을 다시 그린다.
4. 자동 가입 방지(`signup.bot_check`가 켜져 있을 때):
   - `website`에 값이 있음 → `bot` 기록, 오류 F1
   - `form_token`이 없거나 세션에 없음 → `bot` 기록, 오류 F1(새 토큰으로 다시 그림)
   - 발급 후 30분이 지남 → 기록 없음, 오류 F2(새 토큰으로 다시 그림)
   - 발급 후 3초 미만 → `bot` 기록, 오류 F3(같은 토큰)
5. `BEGIN IMMEDIATE` → 24시간 지난 기록 정리 → 횟수 확인. 한도면 `ROLLBACK` 후 `limit_ip`/`limit_site` 기록, 오류 F4/F5.
6. 계정 생성(SNS는 연결까지, 기존 로직) → `ok` 기록 → `COMMIT` → 토큰 소모 → 기존 흐름(로그인, 블로그로 이동).

`action=check`(중복 확인 버튼)는 4·5를 거치지 않는다(기존 세션 제한 5분 30번만).

## 화면 문구

오류는 폼 위에 `role="alert"`로 보이고, 입력값(비밀번호 제외)은 유지한다. 응답 코드는 지금처럼 200(폼 다시 그림), 성공은 302.

| 번호 | 경우 | 문구 |
| --- | --- | --- |
| F1 | 숨은 칸 채움·토큰 없음 | 가입을 처리하지 못했어요. 화면을 새로 고친 뒤 다시 시도해 주세요. |
| F2 | 토큰 만료(30분) | 가입 화면을 연 지 30분이 지났어요. 입력한 내용을 확인하고 다시 눌러 주세요. |
| F3 | 3초 미만 | 너무 빨리 보냈어요. 입력한 내용을 확인하고 다시 눌러 주세요. |
| F4 | 같은 IP 한도 | 이 곳에서 1시간 안에 가입을 너무 많이 했어요. 잠시 뒤 다시 시도해 주세요. |
| F5 | 사이트 전체 한도 | 지금 가입이 몰려 잠시 막아 두었어요. 잠시 뒤 다시 시도해 주세요. |

## GET 화면

- 같은 IP가 이미 한도면 폼 대신 F4, 사이트 전체 한도면 F5 안내를 보인다(기록은 남기지 않음, 로그인 링크 유지).

## 개발 모드

- 횟수 제한은 항상 동작한다(한도는 설정으로 바꿈). `signup.bot_check: false`면 4단계를 건너뛰고 폼에도 두 칸을 넣지 않는다.
